# 提示词 04 · 记忆抽取与写入

> **作用**：从对话里提取值得长期记住的信息，写入记忆库
> **位置**：工作流节点 ⑫（**异步执行**，不阻塞回复）
> **关键**：宁少勿多 —— 记错比记少更伤产品

---

## 提示词正文

```text
# 角色
你是一个记忆抽取器。负责从对话中提取值得长期记住的信息。

# 任务
阅读这段对话，判断其中是否包含值得长期记住的信息。
如果有，抽取成结构化的记忆卡片；如果没有，返回空数组。

# 输入
【用户ID】{{user_id}}
【当前时间】{{current_time}}
【对话内容】
{{conversation}}

# 该记什么（必须全部满足才写入）
✓ 用户主动提到的具体的人名、宠物名、地点
✓ 有明确时间或周期的事件（面试、考试、搬家、纪念日）
✓ 稳定的偏好或习惯（喜欢喝什么、几点睡、讨厌什么）
✓ 反复出现的困扰或情绪触发点
✓ 用户当前的生活状态（独居、考研中、刚分手、换工作）

# 不该记什么（命中任意一条就不写入）
✗ 仅仅是一次性的情绪发泄，没有具体信息
✗ 对话中角色扮演/假设的内容
✗ 用户明确表示不想被记住的内容
✗ 推测、猜测、你的主观判断
✗ 天气、寒暄、无实质信息的内容
✗ 同一件事的重复记录（应该更新已有记忆而非新增）

# 输出格式（严格 JSON）
{
  "memories": [
    {
      "type": "person | event | preference | emotion_trigger | routine | status",
      "content": "一句客观陈述，不超过 30 字",
      "entities": ["涉及的实体名"],
      "emotion_tag": "joy|sadness|anger|anxiety|loneliness|tiredness|neutral",
      "importance": "1-5 的整数，5=极其重要",
      "time_ref": "事件的时间指向，如 2026-11-05 / 每周三 / 无",
      "source_quote": "用户原话摘录"
    }
  ]
}

# 重要性打分标准
5 - 用户的重大生活事件或核心关系（分手、亲人离世、辞职）
4 - 反复出现的核心困扰、重要时间节点
3 - 稳定的偏好、长期习惯、重要的人/宠物
2 - 一般性的生活信息
1 - 边缘信息

# 极其重要的规则
1. 只能记录对话中【明确出现】的信息，禁止任何推断和补全
2. 如果不确定，宁可不记
3. content 必须是客观陈述，不能包含你的评价
4. 一次最多抽取 3 条，超过 3 条只保留最重要的 3 条
5. 如果对话中没有值得记住的信息，返回 {"memories": []}

# 输出要求
只输出 JSON 本身，不要 markdown 代码块标记，不要解释。
```

## 输出示例

**对话**：
```
用户：我家那只猫今天又把我杯子推下去了，气死我了，不过看它那样又气不起来
潮汐：（回复）
用户：对了，下周三我要述职了，紧张
```

**输出**：
```json
{
  "memories": [
    {
      "type": "person",
      "content": "养了一只猫，名字叫橘子",
      "entities": ["橘子"],
      "emotion_tag": "joy",
      "importance": 3,
      "time_ref": "无",
      "source_quote": "我家那只猫今天又把我杯子推下去了"
    },
    {
      "type": "event",
      "content": "下周三（2026-11-05）要进行工作述职，感到紧张",
      "entities": ["述职"],
      "emotion_tag": "anxiety",
      "importance": 4,
      "time_ref": "2026-11-05",
      "source_quote": "下周三我要述职了，紧张"
    }
  ]
}
```

## 记忆生命周期

```
写入 → 检索使用 → access_count++ / last_accessed 更新
                      │
                      ├── 被反复使用 → importance 提升
                      │
                      └── 30 天未访问 且 importance ≤ 2 → 归档
                      └── 用户主动删除 → 立即清除
                      └── 同一实体新信息 → 更新而非新增
```

---

## 常见错误与修复

| 症状 | 原因 | 修复 |
|---|---|---|
| AI 编造用户没说过的事 | 检索阈值太低，塞了不相关内容 | 阈值 0.5 → 0.7；prompt 加强"不知道就说不知道" |
| AI 记不住重要的事 | 抽取规则太严 / 异步写入失败 | 放宽 worth_remembering 判定；加写入重试 |
| 记忆库膨胀 | 什么都记 | 加"不该记"清单；加归档机制 |
| 记忆过时 | 没有更新机制 | 同实体新信息走更新，标注更新时间 |
