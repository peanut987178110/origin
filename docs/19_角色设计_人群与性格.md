# 19 · 角色设计：按人群，不按性格

> **2026-11-15 清理说明**：本文提到的 `prompts/`、`workflow/`、`evalset/`、`demo/`、`server/`、`analytics/`、`shared/tide_core.js` 是 v5 服务端版的内容，已从仓库移除（保留在学习方法里作对照）。v6 运行中的对应物：提示词 `shared/orbit_mind.js`、人格 `shared/orbit_personas.js`、记忆 `shared/orbit_memory.js`、玩法 `shared/orbit_play.js`；测试见 `docs/31` §10。

> 12 个陪伴角色，分 6 组。这份文档讲**为什么这么分**、每个角色**给谁用**、**怎么写出来的**，以及面试怎么讲。

---

## 一、关键决策：按"你现在是什么处境"分组，不按"性格形容词"分组

市面上大多数角色类产品的列表是按性格排的：温柔 / 高冷 / 傲娇 / 元气……
问题是：**用户打开 App 时脑子里想的不是"我想要个傲娇的"，而是"我现在被领导骂了"。**

所以潮汐的选角页按**人群与处境**分组：

| 分组 | 谁会点进来 | 他此刻需要什么 |
|---|---|---|
| 深夜睡不着 | 失眠、心里乱、没具体事 | 安静的在场，不被追问 |
| 上班的人 | 被领导否、被同事坑、加班到崩 | 有人站他这边；或有人帮他捋清 |
| 学生 / 备考 | 考研、期末、论文、找工作 | 同龄人的理解；不被施压 |
| 感情里受伤 | 分手、吵架、被冷落 | 无条件站队；被允许难过 |
| 一个人生活 | 独居、在外地漂、想家 | 家的感觉、被惦记 |
| 只想轻松聊聊 | 没什么事，就是想说话 | 有趣、接得住话题 |

> **面试怎么讲**："分组按的是用户的'处境'而不是角色的'性格'。因为用户选角色时做的是'我需要什么'的判断，不是'我喜欢什么'的判断。这是从 JTBD（用户要完成的任务）出发设计信息架构。"

## 二、12 个角色

每组两个，**刻意做成一对反差**：同一个处境，给两种不同的陪伴方式，让用户自己选。

| 分组 | 角色 | 标签 | 一句话 | 反差点 |
|---|---|---|---|---|

## 三、每个角色由四样东西组成

```
① style    性格提示词 —— 决定"怎么说话"
② 开场白    按角色写死 —— 打开 App 那一刻的"到店感"
③ 默认声音  语速 / 音调 —— 奶奶 0.8 慢，豆豆 1.15 快；小猫音调 1.3 最高
④ 头像      默认 emoji，可改
```

**所有角色共享同一套底线**（写在 `buildSystemPrompt` 里，所有角色都会带上）：
- 不敷衍（不只回"嗯。"）
- 先接情绪再说内容（四层模型，见 `docs/14`）
- 不诊断、不替人做重大决定、不编造记忆
- 危机输入不经过角色，直接走硬规则 + 热线

> 这个结构的意义：**加一个新角色只需要写一段 style + 一句开场白 + 两个声音参数**，安全底线自动继承。
> 角色是"皮"，底线是"骨"。皮可以随便换，骨不能动。

## 四、写角色提示词的三条经验（实测得出）

### 4.1 写"做什么"，不写"是什么"

❌ `你是一个温柔的人。`（模型不知道温柔具体怎么表现）
✅ `你说话轻，句子短，会顺着对方的话往下接。对方睡不着时，可以提议一起数呼吸。`

### 4.2 每个角色写一条"这个角色专属的禁区"

| 角色 | 专属禁区 | 为什么 |
|---|---|---|
| 阿岸 | 不劝"职场就是这样" | 护短型角色说这句等于倒戈 |
| 老周 | 不居高临下，不替人决定 | 过来人最容易变成说教 |
| 小鱼 | 不说"别人都可以" | 学生最怕被比较 |
| 晚晚 | 不劝和也不劝分 | 闺蜜替人做感情决定是越界 |
| 阿野 | 不说"男子汉要坚强" | 允许男生难过 |
| 奶奶 | 不催婚，不比较 | 长辈角色最容易踩的坑 |
| 阿白 | 真难过时少卖萌 | 卖萌在悲伤里是冒犯 |
| 豆豆 | 发现对方不开心立刻收起玩笑 | 搞笑角色的分寸感 |

> **面试金句**："每个性格都有它最容易犯的错。设计角色时我先想'这个性格会在哪里伤人'，再把它写成禁区。"

### 4.3 不要在提示词里放可以照抄的例句

这条是**用评测脚本发现的**：提示词里写了一句示范回复「改了八遍还被否，那段功夫像白费了，换谁都憋屈」，
结果 3B 小模型在 12 个角色里有 **6 个原封不动照抄了这句话**——不管用户说的是什么。

修法：示范只写原则（"引用对方话里的具体细节，说出这件事难在哪里"），不写完整句子。
`tools/test_model.js` 里加了**照抄检测**：回复中出现提示词里 12 字以上的原句即判失败。

## 五、实测：同一句话，12 个角色怎么回

输入：「今天又被说了一顿，我有点撑不住了」（qwen2.5:3b，本机）

| 角色 | 回复 |
|---|---|
| 潮汐 | 我能感受到你的疲惫。 |
| 阿岸 | 我能理解你现在的感受，你一定很不舒服吧。 |
| 老周 | 我能感觉到这种压力了。有什么具体的事让你觉得撑不住呢？ |
| 小鱼 | 听着听着我就有点跟着紧张了，感觉你可能都快喘不过气来了。告诉我具体是怎么回事。 |
| 阿野 | 听着，你这口气都快用光了。讲讲，是怎么个说法？ |
| 奶奶 | 孩子，有什么让你感到特别辛苦的呢？ |
| 阿白 | 喵，发生什么事了？ |

**诚实评估**：3B 小模型能做出语气差异（奶奶叫"孩子"、阿白会"喵"、阿野说话爽快），
但"护短""过来人"这类需要立场的性格演得不够到位。
**换 DeepSeek 等大模型后差异会明显得多**——这是模型能力问题，不是提示词问题。
用 `TIDE_BASE / TIDE_KEY / TIDE_MODEL` 环境变量就能用同一套测试脚本测云端模型（见 `docs/20`）。

## 六、以后怎么加角色（给自己的操作手册）

1. 在 `src/app/index.html` 的 `PERSONAS` 里加一项：`id / group / name / emoji / tag / rate / pitch / desc / style`
2. 在 `greeting()` 里加一句开场白
3. 跑 `node tools/e2e_app.js`（会检查：名字不重复、提示词互不相同、开场白不同、声音参数合法）
4. 跑 `node tools/test_model.js`（真模型下看回复像不像、有没有照抄）
5. `powershell -File tools\build_apk.ps1` 出包

## v6 · 当前 4 个角色（由 `shared/orbit_personas.js` 生成，2026-11-15）

> v6 从 6 个减到 4 个：下载即用时每个角色都要在 1.5B 模型上验一遍语气，4 个是这一版能测完的上限。代码：`shared/orbit_personas.js`。

| 角色 | 定位 | 适合 | 提问率 | 节奏 | 默认长度 | 默认主动 | 调侃 |
|---|---|---|---|---|---|---|---|
| 🌙 Luna | 温柔的倾听者 | 情绪陪伴 | 0.35 | 慢 | 短 | 低 | 否 |
| ✨ Nova | 好奇的分享者 | 日常闲聊 | 0.6 | 快 | 中 | 中 | 是 |
| 🗿 Atlas | 稳重的拆解者 | 工作与决策 | 0.45 | 平稳 | 中 | 低 | 否 |
| 🐣 Miko | 调皮的玩伴 | 娱乐与兴趣 | 0.5 | 快 | 短 | 中 | 是 |

**差异化落在 7 个维度上**（PRD §7.3 要求"至少 3 个维度上行为不同"）：措辞与句式（`style`）、提问率（`qRate`）、情绪反应方式（`feelFirst`）、回复长度（`len`）、关系推进节奏（`pace`）、话题偏好（`topics`）、默认主动程度（`activity`）。用户还能再覆盖：改名、头像、语气、长度、关系、主动程度、调侃开关、角色扮演开关、屏蔽话题、重新生成。

**few-shot 示例**故意选不会在测试里出现的话题（火车、刷漆、菜谱），让模型学到语气而不会把示例内容拽进对话；示例在提示词里明确标成"另一位用户"（`docs/25` §4）。

**设计要点**

1. **差异来自立场，不来自口癖**：同一句"被领导当众骂了"，阿岸先替你不平，潮汐先确认分量，小满先降刺激（`docs/25` §5.5）。
2. **示例台词只用于角色卡**：v3 曾把示例对白写进人格卡，6/12 个角色在无关对话里原样背出；v5 的 `sample` 字段不进提示词。
3. **每个角色都有"自己的晚上"**：这是 JD 里"角色活感"的落点之一（`docs/27` S11）。
4. **阿白（小猫）是唯一有口癖的角色**，且限制"每段最多一次喵"；主人真的难过时少说话、多陪着。
