# 19 · 角色设计：按人群，不按性格

> 这份文档讲**为什么这么分组**、每个角色**给谁用**、**怎么写出来的**，以及面试怎么讲。

---

## 一、关键决策：按"你现在是什么处境"分组，不按"性格形容词"分组

市面上大多数角色类产品的列表是按性格排的：温柔 / 高冷 / 傲娇 / 元气……
问题是：**用户打开 App 时脑子里想的不是"我想要个傲娇的"，而是"我现在被 leader 骂了"。**

所以 Orbit 的选角页按**人群与处境**分组：

| 处境 | 谁会点进来 | 他此刻需要什么 | 对应角色 |
|---|---|---|---|
| 深夜睡不着 | 失眠、心里乱、没具体事 | 安静的在场，不被追问 | 🌙 Luna |
| 只想轻松聊聊 | 没什么事，就是想说话 | 有趣、接得住话题 | ✨ Nova |
| 工作 / 决策压力 | 被否、被坑、要不要辞 | 帮他捋清楚，不替他决定 | 🗿 Atlas |
| 一个人待着 | 想找点乐子、想有人玩 | 轻、爱闹、不沉重 | 🐣 Miko |

> **面试怎么讲**："分组按的是用户的'处境'而不是角色的'性格'。因为用户选角色时做的是'我需要什么'的判断，不是'我喜欢什么'的判断。这是从 JTBD（用户要完成的任务）出发设计信息架构。"

## 二、当前 4 个角色（由 `shared/orbit_personas.js` 生成）

> v6 从 6 个减到 4 个：下载即用时每个角色都要在 1.5B 模型上验一遍语气，4 个是这一版能测完的上限。

| 角色 | 定位 | 适合 | 提问率 | 节奏 | 默认长度 | 默认主动 | 调侃 |
|---|---|---|---|---|---|---|---|
| 🌙 Luna | 温柔的倾听者 | 情绪陪伴 | 0.35 | 慢 | 短 | 低 | 否 |
| ✨ Nova | 好奇的分享者 | 日常闲聊 | 0.6 | 快 | 中 | 中 | 是 |
| 🗿 Atlas | 稳重的拆解者 | 工作与决策 | 0.45 | 平稳 | 中 | 低 | 否 |
| 🐣 Miko | 调皮的玩伴 | 娱乐与兴趣 | 0.5 | 快 | 短 | 中 | 是 |

**差异化落在 7 个维度上**（PRD 要求"至少 3 个维度上行为不同"）：

| 维度 | 字段 | 说明 |
|---|---|---|
| 措辞与句式 | `style` | 短句/长句、口语/书面、感叹号多少 |
| 提问率 | `qRate` | 0 = 几乎不主动问，1 = 每句都想接话 |
| 情绪反应方式 | `feelFirst` | 先接情绪，还是先给结构 |
| 回复长度 | `len` | 短 / 中 / 长 |
| 关系推进节奏 | `pace` | 多久进入下一阶段 |
| 话题偏好 | `topics` | 更愿意聊什么 |
| 默认主动程度 | `activity` | 主动消息的默认频率 |

用户还能再覆盖：改名、头像、语气、长度、关系、主动程度、调侃开关、角色扮演开关、屏蔽话题、重新生成。

**few-shot 示例**故意选不会在测试里出现的话题（火车、刷漆、菜谱），
让模型学到语气而不会把示例内容拽进对话；示例在提示词里明确标成"另一位用户"（`docs/25` §4）。

## 三、每个角色由四样东西组成

```
① style    人格提示词 —— 决定"怎么说话"
② 开场白    按角色写死 —— 打开 App 那一刻的"到店感"
③ 默认声音  语速 / 音调 —— 决定 TTS 读出来的感觉
④ 头像      默认 emoji，可改
```

**所有角色共享同一套底线**（写在稳定段里，所有角色都会带上）：
- 不敷衍（不只回"嗯。"）
- 先接情绪再说内容（`docs/14` 四层模型）
- 不诊断、不替人做重大决定、不编造记忆
- 危机输入不经过角色，直接走规则路由 + 热线
- 11 类输出守卫逐句检查，命中即删这一句

> 这个结构的意义：**加一个新角色只需要写一段 style + 一句开场白 + 两个声音参数**，安全底线自动继承。
> 角色是"皮"，底线是"骨"。皮可以随便换，骨不能动。

## 四、写角色提示词的三条经验（实测得出）

### 4.1 写"做什么"，不写"是什么"

❌ `你是一个温柔的人。`（模型不知道温柔具体怎么表现）
✅ `你说话轻，句子短，会顺着对方的话往下接。对方睡不着时，可以提议一起数呼吸。`

### 4.2 每个角色写一条"这个角色专属的禁区"

| 角色类型 | 专属禁区 | 为什么 |
|---|---|---|
| 倾听型（Luna） | 不急着给建议 | 倾听型角色一开口给方案，立场就没了 |
| 好奇型（Nova） | 对方难过时先收起兴奋 | 高能量角色在悲伤里是冒犯 |
| 理性型（Atlas） | 不把"帮你分析"变成说教 | 拆解型最容易变成老师 |
| 玩伴型（Miko） | 发现对方不开心立刻收起玩笑 | 搞笑角色的分寸感 |

> **面试金句**："每个性格都有它最容易犯的错。设计角色时我先想'这个性格会在哪里伤人'，再把它写成禁区。"

### 4.3 不要在提示词里放可以照抄的例句

这条是**用测试发现的**：v3 时提示词里写了一句完整示范回复，
结果 3B 小模型在 12 个角色里有 **6 个原封不动照抄**——不管用户说的是什么。

修法：示例只写原则（"引用对方话里的具体细节，说出这件事难在哪里"），不写完整句子；
v6 的 few-shot 明确标注"另一位用户"，且话题与测试集错开。

## 五、实测：同一句话，4 个角色怎么回

输入示例（模拟器，真模型）：用户说「今天又被说了一顿，我有点撑不住了」

| 角色 | 典型反应 | 差异在哪 |
|---|---|---|
| Luna | 先停一下，问"是哪句话最难受" | 慢、短、不追问细节 |
| Nova | 先接住委屈，再带一点"我陪你骂两句" | 快、有能量 |
| Atlas | 先确认事实，再问"你想解决还是只想说说" | 稳、结构先行 |
| Miko | 先缓和气氛，再小心地问 | 轻，但不回避 |

**诚实评估**：1.5B 端侧模型能做出语气差异（长度、提问率、节奏），
但"立场"这类需要理解的差异演得不够到位。**这是模型能力问题，不是提示词问题。**
`docs/31` §10.7 有完整 E2E 记录。

## 六、以后怎么加角色（操作手册）

1. 在 `shared/orbit_personas.js` 的 `PERSONAS` 里加一项：`id / name / emoji / style / qRate / feelFirst / len / pace / topics / activity`
2. 改写对应的开场白（`opener`），中英各一份
3. 跑 `node tools/verify_app.js`（会检查：4 个角色的台词互不相同、双语齐全、声音参数合法、7 维有差异）
4. 跑 `node tools/orbit_e2e.js device`（真模型下看回复像不像）
5. `powershell -File tools\build_apk.ps1` 出包

| 🐱 阿白 / Mochi | 小猫 | 想要点软乎乎的陪伴 | 喵。今天辛苦了，我把肚皮借你靠一下。 | 在窗台晒月亮；刚把毛线球弄丢了；在纸箱里打盹 | 蜷在被子角上，耳朵还竖着；半夜在追自己的尾巴 | 1.12 / 1.3 |

**v5 的设计要点（历史）**

1. **差异来自立场，不来自口癖**：同一句"被领导当众骂了"，阿岸先替你不平，潮汐先确认分量，小满先降刺激。
2. **示例台词只用于角色卡**：v3 曾把示例对白写进人格卡，6/12 个角色在无关对话里原样背出；v5 的 `sample` 字段不进提示词。
3. **每个角色都有"自己的晚上"**：这是 JD 里"角色活感"的落点之一（`docs/27` S11）。
4. **阿白（小猫）是唯一有口癖的角色**，且限制"每段最多一次喵"；主人真的难过时少说话、多陪着。

## 历史 · v3 的 12 个角色（规则引擎版，2026-10）

> v3 是纯规则引擎原型，角色只是模板前缀。保留在这里是为了说明**为什么后来放弃了"多角色"**：
> 角色越多，越难在真模型上逐个验语气；12 个角色里有 6 个会照抄示例。

| 分组 | 角色 | 一句话 |
|---|---|---|
| 深夜睡不着 | 潮汐 / 小满 | 安静陪伴 / 带你放松 |
| 上班的人 | 阿岸 / 老周 | 站队发泄 / 理性梳理 |
| 学生 / 备考 | 小鱼 / 木老师 | 陪吐槽 / 帮你找最小一步 |
| 感情里受伤 | 晚晚 / 阿野 | 细腻共情 / 爽快发泄 |
| 一个人生活 | 奶奶 / 阿白 | 长辈的惦记 / 无条件的陪伴 |
| 只想轻松聊聊 | 豆豆 / 凌 | 轻松搞笑 / 有深度地聊 |

**三条角色设计经验（从 v3 总结，v6 仍在用）**：

1. **写"做什么"，不写"是什么"**——"你是一个温柔的人"模型演不出来，"你说话轻、句子短、会顺着对方往下接"可以。
2. **每个角色写一条专属禁区**——先想"这个性格会在哪里伤人"。
3. **不要在提示词里放可以照抄的例句**——示例要写成原则，或者标注成"另一位用户"。
