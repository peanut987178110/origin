
# 从《恋与深空》PRD 到 Orbit 自己的小玩法

> 依据：用户提供的《恋与深空》PRD V2.0 + 设计说明 V3.0（用户明确允许"不合理的地方可以修改"）。
> 原则：**只借机制，不借任何角色、台词、美术、数值文案**。玩法里的每一句话、每一只娃娃、每一个角色反应，都是 Orbit 四位伙伴（Luna / Nova / Atlas / Miko）自己的。
> 这一版没有新增任何埋点之外的"成绩数字"；下表的数字都是代码里的规则常量，不是运营数据。

## 1. 从 PRD 里取用的机制 → 落在哪里

| PRD / 设计说明里的机制 | 取用 | 规则（代码里） | 位置 |
|---|---|---|---|
| 抓娃娃（限次、按位置判定、伙伴换你抓一次） | ✅ | 每天 3 局，每局 3 次抓取（你 2 次、她 1 次）；判定是整数距离 `dx²+dy² ≤ 40²`，不是随机数；她的第一抓必中，之后 70/30；她这一抓是本局最后一抓，和 PRD 一样"她抓完就结算" | `shared/orbit_play.js` `attempt/charGrab`，`src/app/js/10_play.js` |

## 2. 我改了 PRD 的地方（以及为什么）

1. **"她抓完就结算"改成"她这一抓就是本局最后一抓，抓完自动给你看结果"。** 原 PRD 留了一个"再点结算"的步骤；实测时一局打完后按钮灰掉、结果要等下次进来才能看（E2E 发现）。现在最后一次抓完（无论你的还是她的）直接打开结果卡。
2. **"换她抓"不再让爪子瞬移到你选的娃娃上。** 原设计是替你把爪子移过去再抓；实测时玩家刚放好爪子就被移走，像在跟玩家抢。现在她的抓只从爪子当前位置**往你选的那只偏一点**，抓不到也不怪你。
3. **她第一抓必中。** 原设计"每次 70%"，意味着每局都可能是"她两次都没抓到"，玩家看到的伙伴太没用。现在是"她第一抓一定中，第二抓 70%"。
4. **邀请频率设为 7 天 3 次、被拒 3 次停 7 天。** 原设计只说"有上限"，具体数字按"陪伴不施压"（PRD §7.6）来定。
5. **没有任何记录之前不邀请。** 原设计没有这条；对一个刚装好的 App 说"上次那只没抓到"是假的。
6. **"每天"以 04:00 为界**（设计说明的口径），按本地时间算——早先版本用 UTC，边界跑到了中午。

## 3. 这一轮（v6.3）在测试中修掉的真实问题

| 问题 | 怎么发现的 | 修复 |
|---|---|---|
| 一次点击抓了两次（第二下落到已经移位的按钮上报错） | 桌面 E2E 用真实触摸点击，attempts 一次多了一条 | 抓取按钮改为 `pointerdown` 触发（按下的瞬间就决定"是哪一局、哪一下"）；同一次按压留下的兼容 click 不再触发；`grabOnce` 只合并 250 ms 内重复的按压 |
| 抓取被拒绝时不说话 | E2E：按钮点了没反应 | 每种拒绝都有具体提示（"先抓一下，再换我来""这局已经结束了""抓的机会用完了"） |
| 一局结束后按钮灰掉、结果看不到 | E2E：`done → Together` 卡在抓娃娃页 | 最后一抓后直接结算并显示结果 |
| 她的抓和你选的不是同一只（同款娃娃挨在一起时） | E2E：玩家抓到 teddy，她也"抓"了旁边那只 teddy | 她只从爪子所在位置朝你选的那只偏一点；如果你选的那只还在架子上，她一定冲它去 |
| 返回按钮被上一页残留的弹层吞掉 | E2E：从邀请进来的抓娃娃页按返回没反应 | 页面跳转前统一关掉弹层（`back()` 已处理；E2E 的 `step` 不再绕过它） |
| 首页到看板的切换偶发 300 ms 以上 | E2E 页面切换计时 | 记录为观察项，未改代码（见 §4） |

### 3.1 2026-11-14 在模拟器上用真实手指又测出一批（全部已修）

这一批不是测试脚本的问题：用 `adb shell input tap` 在 emulator-5556 上一步步点，复现出来的都是用户真会遇到的。

| 问题 | 怎么发现的 | 修复 |
|---|---|---|
| 「换她来抓」在真机上**完全点不动** | 模拟器真实点击，连点两次毫无反应。根因：按钮只有 `data-act`，而 `03_ui.js` 的 `PRESS_ONLY` 让 click 路径对 `claw.*` 直接 return，press 路径又找不到 `data-press` | 补 `data-press="claw.swap"` |
| 结算页「好了」只关弹层、不回一起 | 模拟器：一局打完按「好了」停在抓娃娃页。根因：`claw.done` 用 `openClawRun()` 取局，而它只返回进行中的局，已终止的局取到 `null` | 改取 `runsOf('claw')` 的最后一局 |
| 专注结算的「好了」也点不动 | 同"换她来抓"，只有 `data-act` | 补 `data-press="claw.done"` |
| 从邀请进抓娃娃，按返回卡死 | 模拟器/桌面 E2E：返回键无效。根因：`go('claw',{reset:true})` 把导航栈清成只剩 `claw`，返回变成"退出 App" | 先把栈设成 `['life']` 再进入 |
| 同一天两局抓娃娃各 +20，当天到 40（规则写的是 30） | 模拟器上连打三局看结算数字 | `canCredit` 加上"本笔点数"参数，按 `已发 + 本笔 > 30` 判 |
| 第二局结算也说"今天你们第一次一起做这个" | 同上，读结算文案 | 只有当天最早一笔才写"第一次" |
| 重进页面显示"看结算"而不是自动弹结果 | 桌面 E2E | 这是设计行为（不让结果卡反复糊脸），把测试的期望改成"能看到结果按钮" |

## 4. 还没解决的

- 页面切换偶发 > 300 ms（本机 E2E 里出现 323 / 329 / 407 / 647 ms，P95 被拉到 647 ms）。多在无头浏览器同时跑着本机模型时出现，模拟器上的真实点击还没复测；这一轮不改代码，真机测完再定。
- 抓娃娃的动画很朴素（爪子上下、光效），PRD 里的"演出"没有做——美术成本高，且不是这一版的目标。
- 三个小游戏只做了两个（抓娃娃、共同专注）；PRD 里其余玩法见 §1 "不取"。
