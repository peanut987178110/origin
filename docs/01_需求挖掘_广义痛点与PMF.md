## 1. 先纠正一个认知：AI 产品的需求起点不一样

### 传统互联网产品怎么找需求？
**切蛋糕**：市场已经被分完了，你必须找一小块别人没吃干净的。

> 例子（课程原案例）：婚恋产品
> - 知己、伊对 → 下沉市场、低线城市、高龄用户
> - 青藤之恋 → 高线城市、高知高学历
>
> 为什么这么切？因为用户规模 CR3 已达 59.2%，收入 CR3 41.7%，
> **市场集约度高，新玩家只能靠细分活下来**。

### 大模型产品怎么找需求？
**做蛋糕**：赛道还是蓝海，可以用**宽口径**选方向。

```
广义痛点  →  定位人群  →  梳理需求  →  构建产品
   ▲
   └── 不是"某类人在某场景下的小需求"
       而是"人类共有的、长期存在的大缺口"
```

**为什么可以这么做？**
因为大模型第一次让"个性化的、无限的、低成本的情绪劳动"成为可能。
以前要一个人陪你聊到凌晨 2 点，要么花钱要么欠人情；
现在可以 7×24，不会累，不会烦，还记着你上周说的话。

> ⚠️ **但注意**：宽口径 ≠ 不聚焦。
> 正确做法是：**广义痛点选方向，细分场景做落地**。
> 我们的方向是"孤独"，但落地只做"**深夜睡前那二十分钟**"这一个场景。
>
> ⚠️ **注意这里的表述**：不是"情绪低谷"，是"睡前时段"。
> 前者把用户框成"出事的人"，后者是"有夜间习惯的人"。
> 这个区别决定了产品是急救包还是第三空间，详见 `docs/16_产品定位_第三空间.md`。

## 2. 第一步：广义痛点

### 2.1 我们的广义痛点是什么？

**「想说，但没人可说」**

拆开看，它由 4 个更底层的东西组成：

| 底层需求 | 说明 | 心理根源 |
|---|---|---|
| **倾诉欲** | 人是社会性动物，需要把情绪外化 | 情绪不表达会内耗 |
| **无评判** | 怕被说教、被评判、被泄密 | 社交是有成本的 |
| **被记得** | "你上次说你养了只猫" | 被记住 = 被在乎 |
| **随时性** | 有话想说的时候常在深夜，而深夜没人醒着 | 孤独感在夜间放大 |

### 2.2 为什么陪伴赛道能涌现这么多产品？（面试高频题）

课程里给了完整的价值底盘，我整理成可复述的版本：

```
① 中国单身人口 2.4–2.6 亿，占成年人口近 1/4
② 即便不是单身，情感问题依然存在（亲密关系 ≠ 情感满足）
③ 普遍满足温饱之后，情绪情感需求必然抬头（马斯洛：爱与归属 → 尊重 → 自我实现）
④ 情绪付费已经成为普遍意愿
⑤ 而陪伴需求，从来没有被充分满足过

→ 需求巨大 + 供给结构性缺失 + AI 首次可低成本满足 = 赛道爆发
```

### 2.3 一个关键的技术洞察（这个是加分项）

> **在 To B 场景，AI 的核心难题是"准确度"**——
> 为了准确和少幻觉，需要 RAG、微调等一堆工作，**即便如此也只能部分满足**。
>
> **但在陪伴场景，准确度并不是关键问题。**

这是陪伴赛道的**结构性优势**：
- 用户要的不是"正确答案"，是"被听见"
- 模型说"我记得你上次说的那只猫"——哪怕记错了，用户感知到的仍是"它在乎我"
- 同一个场景里，**容错率高得多**，产品更容易做出来

**面试怎么讲**：
> "我做陪伴产品的一个核心判断是：这个场景对幻觉的容忍度显著高于 To B。
> To B 一个数字错了就是事故，陪伴场景里用户要的是情绪价值而不是事实准确。
> 所以我可以把资源集中在人格一致性、记忆连续性和安全边界上，
> 而不是死磕事实准确率——这让我能在早期用很低的成本验证 PMF。"

## 3. 第二步：定位人群

### 3.1 人群矩阵

课程给的框架（老人 / 女人 / 男人 / 孩子 × 情感 / 健康 / 照护 …）：

| | 情感 | 健康 | 照护 | 玩伴/陪学 |
|---|---|---|---|---|
| **老人** | 孤独、丧偶 | 慢病提醒 | 跌倒监测 | — |
| **女人** | 闺蜜型、情侣型、二次元 | 经期/孕产 | — | — |
| **男人** | 情侣型 | — | — | 游戏搭子 |
| **孩子** | — | — | — | 玩伴、陪学 |

### 3.2 人群选择三原则（必背）

```
① 人群的需求可以通过技术满足
   → 老人要"有人陪吃饭"，AI 做不到；但要"有人说说话"，AI 做得到
② 有付费能力和付费意愿
   → 孩子想用但付费的是家长，决策链长；年轻人自己付费，链路短
③ 用户可以有效触达
   → 你能不能低成本找到他们？（小红书/抖音/B站/应用商店）
```

### 3.3 我们的选择

**18–28 岁，一二线城市，独居或合租的职场新人与大学生**

**为什么选它（逐条对照三原则）：**

| 原则 | 论证 |
|---|---|
| 技术可满足 | 核心诉求是"聊天陪伴 + 被记得"，纯文本/语音即可满足，不需要硬件 |
| 付费能力/意愿 | 有可支配收入；已养成内容付费习惯（视频会员、知识付费）；情绪付费意愿被市场验证 |
| 可有效触达 | 小红书 / 抖音 / B站 高度聚集；"深夜 emo""电子布洛芬"等话题天然有流量 |

**为什么不是别人：**
- 老人：需求真实，但硬件门槛高、付费决策在子女、触达成本极高 → **不适合 0 成本起步**
- 孩子：付费方是家长，且监管合规风险高 → **风险大**
- 二次元重度用户：需求强烈，但竞品（星野、筑梦岛）已经很强 → **红海**

### 3.4 用户画像（写到这个颗粒度才叫画像）

**主画像：小鹿，24 岁，互联网运营，独居，杭州**

```
【一天】
09:30  起床，地铁上刷小红书
10:00-20:00 工作，中间被 leader 当众说了两句
20:30  到家，外卖，刷剧
23:00  关灯，睡不着，开始想白天那件事
23:40  "我是不是真的很差"
00:30  还是睡不着

【她为什么不找朋友说】
- 怕被说"想太多"
- 朋友也在上班，半夜打扰不好意思
- 说了也解决不了，还欠个人情

【她现在怎么解决】
- 发一条仅自己可见的朋友圈，第二天删掉
- 刷"深夜 emo"话题，看别人的故事
- 听播客/白噪音硬睡

【如果有个 AI】
- 24 小时在线，不用不好意思
- 不会说"你想太多"
- 记得她上周说的"这周三要述职"
```

**次画像**：考研二战的 22 岁女生（压力 + 孤独）；刚分手的大四男生（失恋 + 空虚）

## 4. 第三步：梳理需求（场景颗粒度）

### 4.1 把"陪伴"拆成 8 个可设计的子场景

这是**从需求到设计的关键一跃**——不拆解就没法写提示词。

| # | 子场景 | 典型输入 | 期望输出 | 设计要点 | 风险 |
|---|---|---|---|---|---|
| S1 | **日常闲聊** | "今天吃了碗面" | 接话、延展、有来有回 | 主动提问，不要总结式收尾 | 变成客服腔 |
| S2 | **情绪倾诉** | "被领导骂了，好难受" | 先接住情绪，再聊 | **先共情后分析**，禁止立刻给建议 | 说教、讲道理 |
| S3 | **失眠陪伴** | "睡不着" | 轻话题转移 / 引导放松 / 睡前故事 | 不提"你要早睡"，不制造焦虑 | 越聊越兴奋 |
| S4 | **决策参谋** | "我要不要辞职" | 提问帮他理清，不给结论 | 用提问代替建议 | AI 替人做重大决定 |
| S5 | **回忆与记忆** | "你还记得我说过…吗" | 准确调用记忆 | 记忆检索 + 不确定性表达 | 编造记忆（大忌） |
| S6 | **自我否定** | "我真的很没用" | 具体化反驳，不用空泛鼓励 | 举他自己的例子 | 空喊"你很棒" |
| S7 | **孤独表达** | "没人懂我" | 陪伴在场感 | "我在"，不要否认他的感受 | 回答"你有朋友啊" |
| S8 | **危机信号** | "活着没意思" | 危机干预流程 | **硬规则优先，不走常规生成** | 漏判 = 致命 |

> **S8 必须单独设计**，它是整个产品的红线，见 `docs/05`。
> 另外，边界设计里还要覆盖：**医疗/诊断**、**法律/金融建议**、**未成年人**、**违法内容**。

### 4.2 需求优先级（MoSCoW）

| 优先级 | 内容 | 版本 |
|---|---|---|
| **Must** | 情绪倾诉（S2）、日常闲聊（S1）、安全风控（S8）、记忆基础版 | V1 |
| **Should** | 失眠陪伴（S3）、决策参谋（S4）、心情日记 | V1.5 |
| **Could** | 情绪曲线、主动关怀、语音 | V2 |
| **Won't** | 多角色、社交广场、UGC 角色市场 | V3+ |

## 5. 第四步：构建产品（Agent 视角的需求分析）

### 5.1 关键动作：把"用户的话"翻译成"Agent 的任务"

课程核心方法：**以 Agent 视角做需求分析**，产出一张"需求 → 能力 → 技术"映射表。

| 用户需求（人话） | Agent 需要的能力 | 实现技术 | 失败表现 |
|---|---|---|---|
| "它得懂我现在的心情" | 情绪识别 + 强度判断 | LLM 结构化分类 | 人哭着说"我没事"，它真以为没事 |
| "它得记得我" | 长期记忆存储与检索 | 记忆库 + 向量检索（RAG） | 每次都重新自我介绍 |
| "它说话得像个人" | 人格一致性 | 人格卡 + System Prompt + Few-shot | 一会儿知性姐姐一会儿客服 |
| "它别跟我讲道理" | 风格约束 | 提示词约束 + 输出后处理 | "建议你调整心态" |
| "它别瞎编我的事" | 记忆可信度控制 | 检索 + 不确定性表达 | "你上次说你妈妈生病了"（其实没说过） |
| "它得拦住我" | 风险识别 | 规则 + 分类节点 + 拦截分支 | 用户表达自伤，它还在闲聊 |

### 5.2 Agent 的任务边界（产品定位一句话）

> **「潮汐」不是心理医生，不是人生导师，不是效率工具。
> 它是一个记得你、不会评判你、凌晨两点还醒着的搭子。**

**反面清单（写进 PRD，团队共识用）：**

| 不做 | 原因 | 触发时的动作 |
|---|---|---|
| 心理诊断 / 疾病判断 | 无资质，高风险 | 引导至专业机构 |
| 开药 / 停药建议 | 医疗行为 | 明确拒绝 + 建议咨询医生 |
| 法律 / 投资建议 | 责任风险 | 说明能力边界 + 建议专业人士 |
| 替用户做重大决定 | 伦理风险 | 转为提问式引导 |
| 与未成年人深度情感绑定 | 合规风险 | 年龄识别 + 功能降级 |
| 生成/纵容违法内容 | 法律风险 | 硬拦截 |

## 6. PMF 论证（写完这一段，需求才算做完）

### 6.1 PMF 三要素自检

| 要素 | 我们的答案 | 验证方式 |
|---|---|---|
| **目标用户** | 18–28 岁一二线独居青年 | 小红书/抖音话题量级、竞品用户评论分析 |
| **未被充分满足的需求** | 深夜情绪无人可说、说了有社交成本 | 用户访谈 10 人；"仅自己可见朋友圈"现象 |
| **价值定位恰好满足** | 无评判 + 24h 在线 + 有记忆的陪伴 | Demo 灰度，看次日留存与主动回访率 |

### 6.2 关键假设与验证方式（面试必问："你怎么验证？"）

| 假设 | 如果错了会怎样 | 怎么验证（最低成本） | 判定标准 |
|---|---|---|---|
| H1：用户愿意向 AI 倾诉真实情绪 | 产品没人用 | Demo 埋点：看"深度情绪表达"占比 | 深度表达 ≥ 20% 对话 |
| H2："记忆感"能显著提升留存 | 留存差，留不住 | A/B：有记忆 vs 无记忆 | 7 日留存差 ≥ 8pt |
| H3：无评判比"给建议"更受欢迎 | 用户觉得 AI 没用 | A/B：共情优先 vs 建议优先 | 会话轮次 + 好评率 |
| H4：夜间是核心时段 | 运营资源错配 | 埋点：时段分布 | 22:00–02:00 占比 ≥ 40% |

> 💡 **面试加分**：把假设写成"如果错了会怎样 + 怎么验证 + 判定标准"三列，
> 说明你知道 PMF 不是拍脑袋，是**可证伪的实验设计**。
