## 2. 能力边界（JD-2 原话："了解 Prompt / Memory / 多模态 / Agent 的能力边界"）

| 能力 | 它能做好的 | 它做不好的（Orbit 里的证据） | 我们的做法 |
|---|---|---|---|
| **Prompt** | 设定性格、语气、长度 | 不能保证"不编造"：小模型无视"你什么都不记得"仍可能回答"记得" | 不给它编的机会：召回阈值 0.12、一次最多 2 条（`docs/26`） |
| | | 会照抄示例：v3 时 6/12 角色背出同一句示例 | few-shot 标注"另一位用户"，话题与测试集错开（`docs/25` §4） |
| **Memory** | 规则抽取对"明确说过的事实"命中稳定 | 同义、代称、跨语言：留出集只有 7/12 | 同义词表 + 事件到期日加权；定好换向量检索的条件（ADR-15） |
| | 抽取明确的事实 | 记错比记少更伤人；抽取准确率**还没测** | 宁少勿多、可查看可删除；人工标注评测列入待办 |
| **多模态** | 语音朗读（逐句 TTS）、语音输入（系统 ASR） | 语音情绪识别不可靠；语音交互延迟高 | 只做"读出来"和"说进去"，不做语音情绪判断（ADR-01）；图片入口如实提示 V1.1 |
| **Agent** | 多步任务、调工具 | 安全决策不能交给"模型判断要不要转介" | 危机是**路由**不是**判断**：命中就走固定流程（ADR-02） |
| | | 端侧多轮工具调用 = 更多 token = 更慢 | 12 步链路里只有"生成"靠模型，其余 11 步是规则 |

## 3. 面试题库（25 题）

答案只给要点和出处。**练习方法**：先自己说一遍并录音，再对照要点和出处文档。

### A. 产品与定位

1. **你这个产品的目标用户是谁？为什么是他们？**
   要点：海外 18+、有睡前独处习惯、"有点话想说"的人；不是正在危机中的人（那是底线不是核心场景）；频率决定关系感。→ `docs/16`、ADR-11

2. **和 Character.AI、Replika 有什么区别？**
   要点：先说它们的定位（用 `docs/29` 的数据和 `docs/10` 的拆解），再说 Orbit 的取舍：不做恋爱 / 不做 NSFW / 不做无限角色市场，做"少而精、记得你、不越界"，而且是**端侧**——不联网、不上传。

3. **为什么首发只有 4 个角色？**
   要点：端侧 1.5B 上每个角色都要单独验语气，4 个是这一版能测完的上限；角色越多越难验，v3 试过 12 个，有 6 个会照抄示例。→ `docs/19`、ADR-17

4. **你怎么理解"角色活感"？**
   要点：它有自己的时间（深夜也醒着）+ 它记得你（追问、回访承接）；不是更多口癖。→ `docs/27` S11

### B. 体验设计

5. **新手引导你怎么设计？怎么衡量？**
   要点：一个问题 → 推荐 → 开场白接住；指标看每个选项的激活率（`onboarding_choice`）和 `persona_browse` 比例。

6. **用户情绪很重时，AI 应该怎么回？**
   要点：四层模型；越重越短；不说"一切都会好起来"；测试里给"奶奶走了"设了 120 字上限。→ `docs/14`、`docs/25` §5.3

7. **付费墙怎么设计才不伤害体验？**
   要点：软上限——不切断当前这句，角色先道晚安，0.9 秒后再出付费墙；危机回复不扣额度。

8. **召回推送怎么做才不招人烦？**
   要点：只推用户说过的具体事；一天最多一条；用户手动开启；A/B 同时看留存和关通知率。→ ADR-12

### C. 技术理解

9. **讲讲你们的提示词结构。**
   要点：8 个区块；为什么放服务端；禁止清单写句子。→ `docs/25` §2

10. **RAG 是怎么做的？为什么不用向量库？**
    要点：开卷考试比喻；关键词 + 同义词；量级小、零成本、可解释；**留出集 7/12 是真实上限**（自建集 20/24，中性句误召回 0/5）。→ `docs/26` §5.2

11. **怎么防止 AI 编造用户没说过的事？**
    要点：三层——提示词明确"记忆里没有的不能编"、抽取宁少勿多、召回阈值 0.12 宁缺毋滥。
    v6 **没有**专门的"记忆陷阱"功能（那是 v5 的），思路是"根本不给它编的机会"。

12. **AI 回复太敷衍怎么办？**
    要点：守卫判定（太短 / 复读用户原话 / 重复上一轮）→ `RETRY_HINT` 升温重生成一次 → 仍不行就用兜底话术并埋 `quality_fallback`。→ `shared/orbit_mind.js` `guardReply`

13. **危机识别怎么做？漏判了怎么办？**
    要点：规则词表（离线也能拦）；不调模型；按国家给热线（美国 988 / 中国 12356 / findahelpline）；已知局限是换说法会漏，计划加 LLM 分类层；最坏情况必须是"多拦"不是"漏"。→ `docs/27` S2

14. **为什么把模型放进手机，而不是做服务端？**
    要点：v5 就是服务端版，问题是**用户走不到模型那一步**（要部署、要注册、要填 Key、还要等服务端超时）。
    端侧换来零门槛、零边际成本、隐私；代价是模型从云端大模型变成 1.5B，用规则兜住"必须准"的部分。→ ADR-18

### D. 数据

15. **你们的北极星指标是什么？为什么不是使用时长？**
    要点：周有对话夜数；时长长不一定好（凌晨三点聊两小时可能是失败信号）。→ `docs/13` 末尾 v6 一节

16. **激活怎么定义？留存怎么算？**
    要点：激活 = 24 小时内 ≥3 条消息；Dn 分母只算注册满 n 天的设备，否则新用户拉低留存。→ `docs/13`

17. **你会怎么分群？**
    要点：先用产品里天然的自报维度（角色、引导选项、语言、地区），再用行为维度（一周来几天），最后才考虑模型打标签。→ `docs/13`

18. **A/B 测试结果显示 nudge 组 D7 高了 15 个点，能上线吗？**
    要点：先看显著性（合成数据里 z=1.01，不显著）；再看护栏（关通知的人多了没有）；再看样本量与时长。→ `docs/13`、`shared/orbit_life.js` 实验定义

19. **你怎么确认数据口径是对的？**
    要点：v6 是本地埋点（53 个事件）+ 看板；v5 用"已知答案的合成数据集"逐项比对 35 个数的做法只作方法论讲。
    合成数据一律打 `SYNTHETIC` 水印，不能当真实数据讲。

### E. 商业与合规

20. **单位经济算过吗？**
    要点：要**分开讲两版**。
    v5 云端（历史口径）：每轮约 $0.00085（DeepSeek 官网高峰价，保守）；轻中度 Plus 毛利 78–83%；天天用满会亏 23%。→ `docs/07` v5、ADR-14
    v6 端侧（现在）：**每轮边际成本 = 0**，成本变成固定的模型与分发成本；生死线从"token 价格"变成"1.07 GB 的包有多少人愿意下"。→ ADR-18

21. **海外上线要注意哪些合规？**
    要点：AI 身份披露、危机转介、未成年人保护（18+ 门槛）、数据不出设备、数据可删。
    具体法条和日期以 `docs/29` / `docs/12` 为准；没核实过的法条不引用。

22. **这个产品最大的风险是什么？**
    要点：情感依赖与未成年人（监管和伦理）；危机漏判（换说法）；端侧模型能力上限（1.5B）；"记错"伤害信任；1.07 GB 的下载门槛。各自对应的护栏见 `docs/08_PRD_Orbit_v6.md` §7。

### F. 项目经历

23. **这个项目里你做过的最重要的一个决定？**
    推荐讲 **ADR-18（从云端改端侧）**：判断的起点不是"模型不够好"，而是"用户走不到模型那一步"；
    代价是新模型能力下降，应对是把"必须准"的部分全部交给规则。
    也可以讲 ADR-15（用留出集纠正乐观）。

24. **项目有什么遗憾？**
    要点：真机没测（速度数字都是模拟器上的）；没有真实用户；记忆抽取准确率没测；危机识别只有规则词表。
    每一项都要说出"下一步怎么做"。→ `docs/08_PRD_Orbit_v6.md` §9、§10

25. **你的数据是真实的吗？**
    要点：如实说——没有真实用户数据；测试是自动化 + 模拟器 + 真模型；看板里 400 人是合成数据；市场数据都有来源和分级。
    **这道题答得诚实，比任何漂亮数字都加分。**
