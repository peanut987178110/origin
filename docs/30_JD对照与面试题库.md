## 2. 能力边界（JD-2 原话："了解 Prompt / Memory / 多模态 / Agent 的能力边界"）

| 能力 | 它能做好的 | 它做不好的（潮汐里的证据） | 我们的做法 |
|---|---|---|---|
| **Prompt** | 设定性格、语气、长度 | 不能保证"不编造"：3B 模型无视"你什么都不记得"仍回答"记得" | 记忆陷阱硬规则（ADR-16） |
| | | 会照抄示例：6/12 角色背出同一句示例 | 人格卡不放示例；照抄检测 |
| **Memory** | 关键词检索在字面重合时 100% 命中 | 同义、代称、跨语言：留出集只有 50% | 同义词表止血，定好换向量检索的条件（ADR-15） |
| | 抽取明确的事实 | 记错比记少更伤人；抽取准确率**还没测** | 宁少勿多、可查看可删除；人工标注评测列入待办 |
| **多模态** | 语音朗读、语音输入（系统 TTS / ASR） | 语音情绪识别不可靠；语音交互延迟高 | 只做"读出来"和"说进去"，不做语音情绪判断（ADR-01）；图片、视频暂不做 |
| **Agent** | 多步任务、调工具 | 安全决策不能交给"模型判断要不要转介" | 危机是**路由**不是**判断**：命中就走固定流程（ADR-02） |

## 3. 面试题库（25 题）

答案只给要点和出处。**练习方法**：先自己说一遍并录音，再对照要点和出处文档。

### A. 产品与定位

1. **你这个产品的目标用户是谁？为什么是他们？**
   要点：海外 18+、有睡前独处习惯、"有点话想说"的人；不是正在危机中的人（那是底线不是核心场景）；频率决定关系感。→ `docs/16`、ADR-11

2. **和 Character.AI、Replika 有什么区别？**
   要点：先说它们的定位（用 `docs/29` 的数据和 `docs/10` 的拆解），再说潮汐的取舍：不做恋爱 / 不做 NSFW / 不做无限角色市场，做"少而精、记得你、不越界"。

3. **为什么首发只有 6 个角色？**
   要点：推荐好解释；双语测试成本；先看分群数据再加。→ ADR-17

4. **你怎么理解"角色活感"？**
   要点：它有自己的时间（深夜也醒着）+ 它记得你（追问、回访承接）；不是更多口癖。→ `docs/27` S11

### B. 体验设计

5. **新手引导你怎么设计？怎么衡量？**
   要点：一个问题 → 推荐 → 开场白接住；指标看每个选项的激活率（`onboarding_choice`）和 `persona_browse` 比例。

6. **用户情绪很重时，AI 应该怎么回？**
   要点：四层模型；越重越短；不说"一切都会好起来"；测试里给"奶奶走了"设了 120 字上限。→ `docs/14`、`docs/25` §5.3

7. **付费墙怎么设计才不伤害体验？**
   要点：软上限——不切断当前这句，角色先道晚安，0.9 秒后再出付费墙；危机回复不扣额度。

8. **召回推送怎么做才不招人烦？**
   要点：只推用户说过的具体事；一天最多一条；用户手动开启；A/B 同时看留存和关通知率。→ ADR-12

### C. 技术理解

9. **讲讲你们的提示词结构。**
   要点：8 个区块；为什么放服务端；禁止清单写句子。→ `docs/25` §2

10. **RAG 是怎么做的？为什么不用向量库？**
    要点：开卷考试比喻；关键词 + 同义词；量级小、零成本、可解释；留出集 50% 是天花板证据。→ `docs/26`

11. **怎么防止 AI 编造用户没说过的事？**
    要点：三层——提示词、抽取宁少勿多、记忆陷阱硬规则；第三层是实测发现前两层不够后加的。

12. **AI 回复太敷衍怎么办？**
    要点：判定（<5 字）→ 追加提示 → 升温重生成 → 最多两次；`retries` 埋点算敷衍率。

13. **危机识别怎么做？漏判了怎么办？**
    要点：词表双层（离线也能拦）；不调模型；按国家给热线；已知局限是换说法会漏，计划加 LLM 分类层；最坏情况必须是"多拦"不是"漏"。→ `docs/27` S2

14. **为什么要自己做服务端，不让用户填 API Key？**
    要点：普通用户不会填；没有服务端就没有额度、订阅、埋点、A/B；提示词不能被绕过。→ ADR-13

### D. 数据

15. **你们的北极星指标是什么？为什么不是使用时长？**
    要点：周有对话夜数；时长长不一定好（凌晨三点聊两小时可能是失败信号）。→ `docs/13` v5 §3

16. **激活怎么定义？留存怎么算？**
    要点：24 小时内 ≥3 条；Dn 分母只算注册满 n 天的设备，否则新用户拉低留存。→ `queries.sql` 开头注释

17. **你会怎么分群？**
    要点：先用产品里天然的自报维度（角色、引导选项、语言、地区），再用行为维度（一周来几天），最后才考虑模型打标签。→ `segments`、`usage_tier`

18. **A/B 测试结果显示 nudge 组 D7 高了 15 个点，能上线吗？**
    要点：先看显著性（合成数据里 z=1.01，不显著）；再看护栏（关通知的人多了没有）；再看样本量与时长。

19. **你怎么确认 SQL 写对了？**
    要点：已知答案的合成数据集，逐项比对 35 个数；合成数据打水印，不能当真实数据讲。

### E. 商业与合规

20. **单位经济算过吗？**
    要点：每轮约 $0.00085（DeepSeek 官网高峰价，保守）；轻中度 Plus 毛利 78–83%；天天用满会亏 23%；设 P95 阈值而不是提前降额度。→ `docs/07` v5、ADR-14

21. **海外上线要注意哪些合规？**
    要点：AI 身份披露、危机转介、未成年人保护、部分地区年报转介次数。具体法条和日期以 `docs/29` / `docs/12` v5 一节为准。

22. **这个产品最大的风险是什么？**
    要点：情感依赖与未成年人（监管和伦理）；危机漏判；尾部用户成本；"记错"伤害信任。各自对应的护栏。

### F. 项目经历

23. **这个项目里你做过的最重要的一个决定？**
    推荐讲 ADR-16（用实测推翻"提示词就够了"）或 ADR-15（用留出集纠正乐观）。

24. **项目有什么遗憾？**
    要点：没有真实用户访谈；线上模型没用真实 Key 跑过；抽取准确率没测。并说出每一项"下一步怎么做"。→ `docs/24` §1 第三栏

25. **你的数据是真实的吗？**
    要点：如实说——没有真实用户数据；测试是自动化 + 本机小模型；市场数据都有来源和分级。**这道题答得诚实，比任何漂亮数字都加分。**
