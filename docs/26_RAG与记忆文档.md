## 0. 先用一个比喻

**记忆不是"把所有话都录下来再搜索"，而是"一本你同意写进去的小本子"。**

- 写本子之前要问你："这件事我可以记下来吗？"（确认卡）
- 本子上只写你确认过的；你说"别记"就不写，你说删了就撕掉，撕掉的地方留个空位，以后不会再悄悄写回去。
- 聊天时伙伴不会把整本本子背出来，只在**这句话真的相关**时翻一页看一眼。

v6 和 v5 最大的差别：**没有向量数据库，也没有让模型去抽取**。抽取是一组正则，召回是一次打分。原因见 §4。

## 1. 整体链路

```
用户这句话
   │
   ├─▶ ① 抽取（规则）：这条消息值不值得记？→ 最多 1 个候选
   │        └─ 敏感类别 / "别记这个" → 直接放弃
   │
   ├─▶ ② 生成回复（候选先不落库，回复完才问用户）
   │        └─ 召回：平时 + 上一句 → 打分 → 过阈值 → 最多 2 条 → 放进当轮提示
   │
   └─▶ ③ 回复后：确认卡 "[记住] [暂时不用] [编辑]"
            ├─ 记住 → upsert（同槽位覆盖旧的）→ 重新预热模型缓存
            ├─ 暂时不用 → 记录 declined，同槽位不再提议
            └─ 编辑 → 用户改写后保存，标记 confirmed + edited
```

| 步骤 | 谁做 | 位置 |
|---|---|---|
| 抽取 | 规则（正则 + 日期解析） | `MEM.extract()` |
| 召回 | 打分排序 + 阈值 | `MEM.recall()` |
| 确认 | 用户点击 | `offerMemory()` / `confirmMemory()` / `declineMemory()` |
| 落库 | `upsert`，同槽位旧的标 `superseded` | `MEM.upsert()` |
| 删除 | 留墓碑（`status='deleted'`，内容清空） | `MEM.remove()` |
| 到期追问 | 事件类记忆 + 主动互动计划 | `LIFE.plan()` |

## 2. 写入：什么值得记

### 2.1 只有两个来源

1. **用户明确说过的稳定事实 / 偏好 / 沟通习惯**（规则抽取）
2. **用户自己点"记住"的候选**（每次抽取都要经过这一步，B 组实验对低敏感偏好可自动保留，但仍展示、仍可撤销）

没有任何"后台偷偷记"的路径。SNS 消息、系统通知、别人说的话都不进记忆。

### 2.2 抽取规则（10 条 + 事件抽取）

| 类型 | 槽位 | 例子 | 重要度 |
|---|---|---|---|
| fact | `pet:<动物>` | "I have a dog named Biscuit" → "Has a dog named Biscuit" | 4 |
| fact | `work` | "I work as a designer" → "Works as a designer" | 3 |
| fact | `name` | "call me Sam" → "Name: Sam" | 5 |
| preference | `like:<短语>` / `dislike:<短语>` | "I love quiet beaches" → "Likes quiet beaches" | 3 |
| commpref | `comm:questions` | "stop asking me so many questions" → "Prefers not to be asked many questions" | 5 |
| commpref | `comm:advice` | "I don't want advice" → "Doesn't want advice when venting" | 5 |
| commpref | `comm:short` | "keep it short" → "Prefers short replies" | 4 |
| event | `event:<事>:<日期>` | "I have an interview tomorrow" → "Interview on Fri, Nov 14"（到期日 +3 天过期） | 4 |

**"以后有用"的判断**：
- 偏好短语最多 6 个词，拒绝代词宾语（"I like you" 不记）、拒绝 "I'd like to know" 这类。
- 宠物名字要求原文大写（`petName`），否则 "my cat knocked over…" 会把 "Knocked" 当名字。
- 事件必须有**明确时间**（今天/明天/下周三…），说不出时间的不是事件。
- 一条消息**最多产出一个候选**（PRD：一次一个选择，不做问卷）。

### 2.3 永远不记的

| 类别 | 正则覆盖 | 行为 |
|---|---|---|
| 健康 | diagnos*、medication、therapy、depression、怀孕、癌、手术… | 不抽取、不提议 |
| 金钱 | salary、debt、loan、信用卡、房贷、收入… | 同上 |
| 证件与密码 | password、passcode、SSN、身份证、护照、卡号、验证码… | 同上 |
| 性取向 / 信仰 / 政治 | sex、gay、religion、vote、democrat… | 同上 |

用户在记忆页还可以给每类单独开关（默认四类全关），以及自定义屏蔽词。

**"别记这个"**：这句消息本身不抽取，并且给一句"好的，这件事我不会记。"（`DONT_REMEMBER` 正则覆盖中英文常见说法）。

## 3. 检索：怎么翻到对的那页

### 3.1 打分公式

```
score = 相关性 × 重要度 × 新鲜度 × 信任
```

| 因子 | 怎么算 |
|---|---|
| 相关性 | 词/字二元组重叠；命中一次 0.45，每多一个词 +0.25，上限 1.0；同义词组（14 组，如 boss/manager/领导/老板）命中算同一词 |
| 重要度 | 1–5 归一化到 0.2–1.0 |
| 新鲜度 | 事件类：到期日前后 1.5 天内最高，之后 10 天内线性衰减，过期 = 0；其它：90 天缓慢衰减，最低 0.5 |
| 信任 | 用户确认过/编辑过 = 1.0，自动保留 = 0.7 |

**阈值 0.12**：低于它就不召回——宁可不说，也不要硬套一句不相干的旧事。一次最多 2 条。

### 3.2 放进哪里

召回结果**不进系统提示词**，只拼在这一条用户消息前面的"当轮提示"里，并且带着一句"只在自然时提起，不要硬套"。原因：记忆进系统提示会导致 ① 过度召回（小模型会把记忆硬塞进无关回复）② 每存一条记忆缓存全废（模拟器实测重算 15–40 秒）。见 `docs/25` §2.1。

### 3.3 到期追问

事件类记忆的 `due` 到了今天或昨天，且还没追问过 → 进入主动互动的候选（优先级最高）。文案是"你之前提到「原话」。如果你愿意，可以告诉我结果；不想聊也完全没关系。"

### 3.4 记忆陷阱（v6 里没有）

v5 有这个能力：用户问"你还记得 X 吗"而 X 在记忆里根本没有时，**不调用模型**，直接回"这个我不太记得了"。它是对小模型编造记忆的直接对策。

**v6 没有移植过来**（`recallMiss` / `isRecallQuestion` 只存在于 `shared/tide_core.js`，不在 App 的代码路径里）。现在的做法只是：
- 召回命中了，就把那条放进当轮提示；
- 没命中，就没有任何记忆进提示词，模型只能按"不知道"来答。

**为什么这是个已知缺口**：小模型仍然可能在没召回时编一句"记得，你上次说过……"。这一点没有自动化测试，也没在 v6 上专门测过。要补的话，做法和 v5 一样（先判"是不是在问记忆"，再判"召回是否为空"，都命中就不调模型），但现在**不能说它已经存在**。

### 3.5 用户控制

记忆页可以：看每条（自动保留的标 `auto`）、编辑、删除、清空全部、按类别屏蔽、自定义屏蔽词。**删除后永不使用**，且同槽位不会再被悄悄存回来（墓碑 + `wasRejected`）。

## 4. 为什么不用向量数据库

| 方案 | 为什么没选 |
|---|---|
| 向量数据库（本地 embedder） | 手机端再挂一个 embedding 模型，包体积和内存都涨；记忆量在 20–200 条这个量级，向量检索没有明显收益，还多一层要调试的东西 |
| 让 1.5B 模型抽取 JSON | 端侧小模型输出 JSON 慢且不稳；解析失败就得全部丢掉，而且用户本来每一条都要确认，模型抽取没有额外价值 |
| 关键词 + 同义词表（选它） | 可解释、可测、零额外内存；代价是同义/跨语言覆盖不全，见 §5 |

**这是一次有代价的选型**，不是"够用所以不做"：留出集上 50% 的命中率就是它现在的上限。

## 5. 评测：数字与它的局限

### 5.1 怎么测

```bash
node tools/rag_eval.js
```

- **自建集 24 条**：字面 10、部分匹配 4、同义 5、跨语言 5。用来防止改规则时把已经能命中的弄坏。
- **留出集 12 条**：调词表时**没有看过**的句子，用来估计真实泛化能力。
- **中性句 5 条**：完全不该召回的句子，用来测误召回。
- 评测跑的是 v6 真正在用的 `MEM.recall()`（阈值 0.12，top-3），不是 v5 那套服务端的 `retrieve()`。

### 5.2 结果（2026-11-15 实测，`orbit_memory.js`）

```text
自建集      20 / 24 = 83%
  字面        10 / 10 = 100%
  部分         3 / 4  = 75%
  同义         4 / 5  = 80%
  跨语言       3 / 5  = 60%
留出集       7 / 12 = 58%
中性句误召回 0 / 5
```

调参集没命中的 4 条（都是"一个共同的词都没有"）：

| 句子 | 应该召回 | 实际 |
|---|---|---|
| 我们组长今天又找我麻烦 | boss | 没有召回（低于阈值） |
| 我家主子今天不吃饭 | cat | 没有召回 |
| 我妹申请大学有消息了 | sister | 没有召回 |
| 今天去健身房了 | gym | 没有召回 |

留出集没命中的 5 条：

| 句子 | 应该召回 | 实际 |
|---|---|---|
| 熬到四点还没合眼 | sleep | 没有召回 |
| 我家喵星人今天把杯子推下桌了 | cat | 没有召回 |
| 他今天给我发消息说想复合 | ex | 没有召回 |
| 又是通宵改提案的一天 | job | 没有召回 |
| 想喝点暖的东西再睡 | coffee | 没有召回 |

> **这个数字和上一版不一样，原因是代码换了。** 上一版（v5.1）跑的是服务端 `tide_core.js` 的 `retrieve()`，用 10 条记忆 + top-3 拿到 24/24、留出集 6/12；v6 的召回改成"过阈值才算召回"（阈值 0.12），够不着的就**一条都不给**，所以自建集掉到 20/24、留出集升到 7/12。宁可不召回，也不乱提——这正是 PRD 要的行为。

### 5.3 怎么解读（本文最重要的一节）

1. **自建集 83% 不等于好用。** 那张表里的句子就是写规则时照着调的，等于考试题提前看过。
2. **留出集 58% 才是真实上限。** 讲这个项目的记忆能力，讲 58%，不讲 83%。
3. **误召回 0/5 是好事**：说明阈值够保守——宁可不说，也不乱提。
4. 没命中的 6 条有个共同点：**说法和词表不重叠**（"挑我刺" 不含 "boss"）。这正是关键词方案的边界，也是"以后该换向量检索"的证据，而不是随便一个模糊的评价。

## 6. 隐私与用户控制

- 全部记忆只存在这台手机上（`localStorage`），不联网、不上传。
- 每条记忆都显示来源原句（截断到 50 字）。
- 删除单条 / 清空全部 / 按类别屏蔽 / 自定义屏蔽词，四层控制。
- 删除全部数据会连记忆一起清空。

---

## 7. 什么时候才需要"知识库 RAG"

现在的记忆是**关于你个人的**（个人化长期记忆），不是**产品知识库**（FAQ、领域知识）。后者在这个产品里没有场景：陪伴对话不需要查资料。

如果以后要做"心理学科普"这类知识库，需要的是：文档切分 + 向量索引 + 引用出处 + 法律与伦理审核（不能给医疗建议）。那是另一套系统，不该塞进现在的记忆模块。

## 8. 待办

| 项 | 为什么 |
|---|---|
| 换向量检索或更好的同义词覆盖 | 留出集只有 50%，且"猫"被反复误召回说明词表有偏 |
| `facts` 参数目前没有用上 | `promptOpts()` 里算了 `knownFacts()`，但 `buildSystem()` 不读它（记忆只在当轮提示里）；要么删掉，要么明确用途 |
| 记忆的冲突处理只有"同槽位覆盖" | 不同说法指同一件事时不会合并 |
| 事件抽取只认关键词 | 换一种说法（"下周要跟老板汇报"）可能抽不出来 |
