## A. 系统工作流

### A.1 比喻：深夜便利店的一次结账

| 便利店 | Orbit |
|---|---|
| 门口保安看一眼（危险人物直接带去警卫室） | **危机硬规则**：命中就转介，不进店、不调模型 |
| 店员问"会员卡呢？"（今天还剩几次） | **额度检查** |
| 店员翻一下你的购物记录 | **记忆召回**（只翻相关的那一页） |
| 店员按员工手册和你聊 | **拼提示词 → 端侧模型生成** |
| 店长在旁边听着，觉得不对就打断 | **逐句输出守卫**（坏句子直接不显示） |
| 收银小票只记几点、买了几样 | **埋点只存元数据** |
| 打烊后，店员把值得记的事写进本子，还要你点头 | **记忆确认卡** |

**和 v5 的差别**：v5 这一切都在服务端，中间隔着一次网络请求；v6 全在手机上，**没有任何一步等网络**。换页面是同步的（同一帧就画出来），回复只在等模型。

### A.2 一轮对话的完整链路

```text
[手机，全部在本机]
用户输入
  │
  ├─① 危机词表命中？（自伤 / 伤人 / 当下危险）
  │     └─ 是 ─▶ 固定话术 + 按国家给热线；**不调模型、不扣额度**
  │              这句话被标 risk，连同它之前的内容一起移出模型上下文
  ├─② 问"你是 AI 吗" ─▶ 按规则如实回答（不调模型）
  ├─③ "忘掉我的 X" ─▶ 先找出一条匹配的记忆，弹确认（不静默删）
  ├─④ 今日额度用完 ─▶ 一句收尾 + 付费墙（不调模型）
  │
  ├─⑤ 理解：情绪标签 + 强度、意图（只想被听 / 要建议 / 想转移注意）
  ├─⑥ 记忆候选：规则抽取，最多 1 个（敏感类别直接放弃）
  ├─⑦ 召回：这句 + 上一句 → 打分 → 过阈值 → 最多 2 条
  │
  ├─⑧ 拼提示词
  │     ├─ 稳定段（缓存）：身份 + 人格 + 关系 + 长度 + 开关 + 沟通偏好 + 6 条规则 + few-shot
  │     ├─ 历史：最多 24 条，按 token 预算按块丢弃（保住缓存前缀）
  │     └─ 当轮提示：阶段 + 上次摘要 + 情绪策略 + 意图 + 召回的记忆 + 是否禁止提问
  │
  ├─⑨ 流式生成
  │     ├─ 每说完一句就过守卫，通过的才显示；正在写的半句原样显示
  │     ├─ 到角色长度的句数就主动停（不等模型自己收尾）
  │     └─ 用户点停止：已有可用句子就留下，没有就删掉整个气泡
  │
  ├─⑩ 守卫判定需要重来 ─▶ 换"重来提示"再生成 1 次（温度 0.7 → 0.9）
  │     仍不行 ─▶ 固定兜底话术 + 埋点 quality_fallback
  │
  ├─⑪ 收尾：额度 +1、记录引擎统计、可选朗读、记忆确认卡、
  │         焦虑/压力/迷茫时给三个快捷选择、第 3 条回复后温和地问要不要通知
  │
  └─⑫ 规划下一次主动互动（见 A.3）
```

**为什么①要"连它之前的内容一起移出上下文"**：只排除危机回复是不够的——模拟器上出现过，危机两轮之后模型说"想结束一切也没关系"。现在只要某条用户消息触发了安全路由，它和它之前的所有内容都不进入模型。

**为什么⑧要把提示词拆成两段**：端侧模型按前缀复用 KV 缓存。任何"稳定段"的改动都会让整段缓存失效，模拟器实测重算 594/660 token（约 33 秒）。所以关系阶段、上次摘要、召回的记忆全部挪到当轮提示里。详见 `docs/25`。

### A.3 其它几条链路

**首次打开（新手引导）**

```text
欢迎页（AI 身份声明 + 18+ 声明）
  ─▶ 年龄：选"未满 18" ─▶ 拦下 + 给当地热线
  ─▶ 选角色（4 个，按"你今晚想要什么"推荐）     埋点 character_selected
  ─▶ 关系（倾听者 / 朋友 / 鼓励者）              埋点 character_configured
  ─▶ 主动程度（低 / 中 / 高）
  ─▶ 完成：AI 先开口（开场白，中英双语）         埋点 onboarding_completed
A/B：onboarding_order_v1 的 B 组把"关系"移进聊天里问
```

**主动互动（planProactive）**

```text
条件（全满足才发）：通知已开 · 不在免打扰时段 · 当天额度未满 · 没有连续被忽略降频
                  · 有值得说的具体事 · 类型没被屏蔽
候选优先级：到期事件 > 兴趣延续（中/高，4 天一次）> 断掉的对话（6 小时~3 天）> 轻互动（仅高）
频率：低/中每天 1 条，高每天最多 2 条；连续 3 次没打开 → 降为隔天
文案铁律：不以"你怎么才来"开头，不说"我想你了"；模板自带"不想聊也完全没关系"
点开 ─▶ 埋点 proactive_message_clicked；没点 ─▶ proactive_message_dismissed，计 ignoreStreak
```

**抓娃娃 / 一起专注 / 共同记录**

```text
抓娃娃：每天 3 局 × 每局 3 次（你 2 次 + 她 1 次）
        你点了「抓」→ 位置判定（爪尖离娃娃 ≤40/1000）→ 命中则娃娃从架子上消失
        你第一次抓之后她才有机会；她抓完这一局就结束；结算只写一次
一起专注：真实秒表，切出页面/切后台照常计时；满 10 分钟才留记录；暂停超 30 分钟自动结束
共同记录：抓娃娃 20 / 专注 10，每天最多 30（按"这笔加上去会不会超"判）；可隐藏，不收回进度
```

**删除全部数据**

```text
设置 ─▶ 删除全部数据 ─▶ 二次确认 ─▶ 清空 localStorage + 取消通知 ─▶ 回到欢迎页
```

### A.4 如果用 Dify / Coze 搭同一条链路

面试官可能会问"这个用低代码怎么搭"：

| Orbit 步骤 | Dify / Coze 节点 | 说明 |
|---|---|---|
| ① 危机词表 | 条件分支 → 直接回复 | 必须放在 LLM 节点之前 |
| ② AI 身份问答 | 条件分支 → 直接回复 | 不让模型临场发挥 |
| ④ 额度 | 代码节点查用户额度 | 平台一般没有内置 |
| ⑤⑥⑦ 情绪 / 意图 / 记忆 | 代码节点 | 个人记忆用代码节点更合适；知识库节点适合文档类 RAG |
| ⑧⑨ 生成 | LLM 节点（系统提示词引用变量） | 但平台的"变量"很难拆成稳定段 + 当轮提示 |
| ⑨ 逐句守卫 | 代码节点 | 平台里做不到"边流式边删句子" |
| ⑩ 重来 | 条件分支 → 第二个 LLM 节点 | 平台里"循环重试"通常要拆成节点 |
| 埋点 | HTTP 节点写数据仓库 | |

**为什么最后没用平台**：① 端侧模型要在手机上跑，平台只能跑在云端；② 逐句流式守卫需要自己控制 token 流；③ KV 缓存复用要靠自己管提示词前缀。这三条平台都给不了。原型验证阶段用平台很快，真做端侧就必须自己写。

## B. 产品工作流：一个需求的一生

JD 原文："负责需求分析、PRD 撰写、项目推进与上线复盘"。下面用这一轮真实做过的事——**「在模拟器上用真手指找到玩法里的 6 个 bug」**——走一遍。

### B.1 七个阶段

| 阶段 | 产出物 | 这个需求里的真实内容 |
|---|---|---|
| 1. 发现问题 | 问题陈述 | 用户说"你做完先自己在模拟器上测试一下"。桌面自动化 129/156 通过，但通过不等于好用 |
| 2. 需求分析 | 需求卡（见 B.2） | 要回答的是"抓娃娃在真触摸下到底通不通"，不是"测试有没有红" |
| 3. 方案设计 | 复现路径 + 判定标准 | 用 `adb input tap` 逐步点、每步截图；每个按钮都要眼见为实 |
| 4. 指标先行 | 判定标准 | 不是指标，是"这一步有没有发生"——按钮有没有响应、有没有回到正确的页 |
| 5. 开发与测试 | 修 + 回归 | 找到 6 个真 bug（`docs/31` §10），逐个修；修完桌面 167/167、模拟器 167/167 |
| 6. 上线 | 发布检查单 | 见 `docs/31` §10.6 |
| 7. 复盘 | 复盘报告 | 写进 `docs/31` §10.8：**上一轮把失败归给测试驱动是错的**，桌面 E2E 报的失败对应的是 App 的真 bug |

### B.2 需求卡模板（以这一轮为例）

```text
【标题】玩法按钮在真机上点不动的问题
【用户】在手机上玩抓娃娃的人
【场景】点「换她来抓」没反应；结算页点「好了」停在原地；从邀请进来点返回卡死
【目标】每一个按钮按下去都要有反应，返回要回到该回的地方
【方案】不改交互设计，只修触达路径：
        · claw.swap / claw.done 补 data-press（这两个动作在 PRESS_ONLY 里，click 路径本来就被跳过）
        · claw.done 取局改用 runsOf('claw') 最后一局（openClawRun 只返回进行中的局）
        · 受邀进入时把导航栈设为 ['life']，不再用 reset:true 清空
        · 关系进度上限按"本笔加上去会不会超 30"判
        · "今天第一次"只在当天第一笔时显示
【不做】不改数值、不改界面、不重做玩法
【指标】每一步"有没有发生"（按钮响应 / 页面跳转），以及三个测试套件的数字
【风险】驱动自己也有缺陷，修 App 的同时要修驱动，否则改完还是红的
【验收】桌面 E2E 167/167；模拟器 device E2E 167/167；抓娃娃全流程截图逐张看过
```

### B.3 复盘模板（上线后填）

```text
1. 目标回顾：当时想解决什么
2. 数据结果：主指标、辅助指标、护栏指标（附口径、样本量、是否显著）
3. 符合预期的：……
4. 不符合预期的：……（先查口径，再查产品）
5. 用户声音：抽样看真实反馈（脱敏）
6. 结论与下一步：保留 / 迭代 / 下线
```

**规矩**：没有真实数据之前，复盘只写"计划看什么"，不写"提升了 X%"。这个项目所有文档都遵守。

### B.4 版本节奏

| 类型 | 节奏 | 例子 |
|---|---|---|
| 提示词 / 文案 | 随时，但每次全量回归（`docs/25` §8） | 禁止清单加一句 |
| 规则 / 玩法 | 小版本（6.x） | v6.3 加抓娃娃、一起专注 |
| 架构变化 | 大版本 | v6 从服务端改成端侧 |

每个大决策写一条 ADR 进 `docs/09`：背景 → 选项 → 决定 → 代价 → 什么情况下推翻。

## C. 本地验证工作流（命令清单）

在项目根目录执行，App 相关全部不需要服务端。

| 目的 | 命令 | 当前结果（2026-11-15） |
|---|---|---|
| 静态架构守卫 | `node tools/verify_app.js` | ✅ 127 |
| 玩法规则单测 | `node tools/orbit_play_test.js` | ✅ 85 |
| 引擎流式解析单测 | `node tools/unit_engine_test.js` | ✅ 4 |
| 记忆检索评测 | `node tools/rag_eval.js` | 自建 20/24，留出集 7/12，中性句误召回 0/5 |
| 文档与交付物自检 | `python -I tools/selftest.py` | ✅ 336 |
| 桌面 E2E（替身模型，只验流程/布局） | `ORBIT_ENGINE=http://127.0.0.1:11500 node tools/orbit_e2e.js web` | ✅ 167 |
| 模拟器 E2E（真触摸 + 真模型） | `node tools/orbit_e2e.js device` | ✅ 167 |
| 打包 APK（含 14 项 Gradle 单测） | `powershell -ExecutionPolicy Bypass -File tools/build_apk.ps1` | ✅ APK 与源码一致 |
| 校验 APK 与源码一致 | `python -I tools/verify_apk.py` | ✅ 逐字节一致 |

**每次改动的顺序**：`build_app` → `verify_app` → `orbit_play_test`（改了玩法才跑）→ `selftest`。改了提示词或玩法，再跑桌面 E2E 和模拟器 E2E。准备交付才打包 APK。

**注意**：`verify_apk.py` 会因为 App 源码比 APK 新而失败——那不是 bug，是提醒你重新打包。
