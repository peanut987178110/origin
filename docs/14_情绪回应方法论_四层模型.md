# 14 · 情绪回应方法论：四层模型

> **这份文档解决一个问题**：「AI 说得都对，但很冷。」
>
> 它是 v3 → v4 迭代的完整记录——包括改错了什么。
> 面试时这段比任何结果数据都好讲，因为它证明你在**做产品判断**，而不是调参。

---

## 一、先说结论

**「聪明但冷」不是词表不够全，是结构错了。**

原来的回复结构是：

```
接住语 → 推论 → 追问
「嗯。   被这样定性，比被人指出具体哪错了难受得多。」
```

这是**分析**。整条回复都在下判断，像咨询师给诊断。
用户此刻要的是「我被看见了」，不是「我被分析了」。

**诊断做对了会让人觉得你懂，做多了会让人觉得你在评判。**

---

## 二、四层模型

情绪回应有四个层次。大多数产品只做第四层，于是显得聪明但没人味。

| 层 | 名称 | 做法 | 例 | 作用 |
|---|---|---|---|---|
| ① | **命名** | 把感受说出来 | 「这听着像是委屈」 | 帮用户认出自己的情绪 |
| ② | **正常化** | 告诉他反应是合理的 | 「换成谁都得这样」 | 解除「我是不是太脆弱」的自我怀疑 |
| ③ | **在场** | 不解释，只陪着 | 「我在」「不用说，我陪着」 | 提供存在感，不索取回应 |
| ④ | **推论** | 往前推一步，说出没说出口的 | 「他不是在否方案，是在否你」 | 制造「被深度理解」的瞬间 |

**正确的顺序是 ①②③ → ④，不是只有 ④。**

原版只做第 ④ 层，所以用户听到的是：**你说得对，但我不想听你说这个。**

---

## 三、为什么是这四层：两个依据

### 3.1 情绪支持对话研究（ESConv）

情绪支持对话的研究框架把有效策略分成八种：

```
提问 / 复述 / 反映感受 / 自我披露 / 肯定 / 提供建议 / 提供信息 / 其他
```

**关键发现**：在情绪支持场景里，「提供建议」和「提供信息」的有效性明显低于
「反映感受」和「肯定」——而后者恰恰是本地图里的 ①②。

> 这解释了一个常见错误：产品经理总觉得"有用"= 给建议。
> 但在陪伴场景，给建议是在降低对方的自主感，反而让人更难受。

### 3.2 Pi 的产品选择（公开资料）

Pi（Inflection AI）的定位刻意不是工具——不做清单、不写代码、不查资料，
只做日常对话。它被描述为「一个有耐心的、不评判的朋友」，核心手法包括：

- **主动倾听**：把对方的感受反映回去
- **互问引导**：用「后来你感觉怎么样？」把话头交回去
- **语气适配**：跟着对方的情绪强度调整自己

**它的成功恰好证明了一件事**：
用户不需要一个更聪明的助手，需要一个**更会在场**的对话者。

> ⚠️ **诚实边界**：以上是公开报道与产品观察，不是我对 Pi 内部实现的逆向分析。
> 面试时若被追问细节，说"这是我从它的公开定位和对话体验里读出来的判断"，
> 不要说"我知道它是怎么做的"。

## 四、策略层设计（v4 的实现）

不是所有情况都该用同一个策略。**情绪强度 × 有没有明确痛点** 决定用哪种。

| 情绪强度 | 有明确痛点 | 策略 | 输出形状 |
|---|---|---|---|
| ≥ 9 | 任意 | **见证 witness** | 一句，「我在」 |
| ≥ 8 | 绝望类（难过/麻木/疲惫/孤独）且说不清 | **见证 witness** | 两句，共振 + 在场 |
| ≥ 8 | 愤怒类，或有明确痛点 | **验证 validate** | 两点，共振 + 「你没错」 |
| 6–7 | 有 | **验证 validate** | 两点 |
| ≤ 7 | 有 | **验证 + 推论 reflect** | 两点 |
| ≥ 5 | 无 | **接住 hold** | 一点，陪着 |
| 低 | 无 | **接话 chat** | 按话题往下聊 |

**三条关键规则：**

```
① 愤怒 ≠ 需要安抚
   愤怒要的是"你没错"，不是"别说了"。
   把愤怒判成"需要陪伴"，等于让人闭嘴——比原版更糟。

② 情绪越重，话越少
   ≥8 分强制 ≤2 句。人在最难受的时候读不进长句子。
   这不是风格问题，是认知负荷问题。

③ 验证/推论型回复最多 2 句
   到第 3 句就开始像讲课了。
```

## 五、这一轮踩的坑（★ 面试最好讲的部分）

> 下面每一条都是**跑探针跑出来的**，不是想出来的。
> 而且有几条是**改完之后才出现的**——这是迭代的真实形态。

### 坑 1 · 把愤怒当成"需要安抚"

| 项 | 内容 |
|---|---|
| **现象** | 「凭什么他可以说我」（愤怒 8 分）→ 回「不用说话，我陪着。」 |
| **为什么糟** | 用户正在表达抗争，你让他别说了。这是**否定用户的表达**，比不回应更伤 |
| **根因** | v4 的策略选择只看强度（≥8 就走 witness），没看情绪类型 |
| **修复** | 愤怒类永远不走 witness，改走 validate，且验证池必须点明「你没错」 |
| **产品意义** | 情绪**类型**比强度更重要。同样是 8 分，愤怒和绝望要完全不同的回应 |

### 坑 2 · 编造用户没经历过的场景

| 项 | 内容 |
|---|---|
| **现象** | 「感觉自己像个废物」→ 共振句回「那几秒钟，应该特别长。」 |
| **为什么糟** | 用户根本没提"几秒钟"。这是**幻觉**，而幻觉在陪伴场景是最伤信任的 |
| **根因** | 写共振句时默认了"有人说了什么"这个场景 |
| **修复** | 定了一条写作铁律：**共振句只能描述 ① AI 自己的反应 ② 用户已说出口的事实** |
| **通用价值** | 这条规则可以直接写进任何陪伴产品的 System Prompt |

**修复前后的对比：**
```
❌ 「那几秒钟，应该特别长。」        ← 假设了"那几秒"
❌ 「被这么说，谁都会愣住。」        ← 假设了"有人这么说"
❌ 「这话听着就扎人。」              ← "这话"无所指
✅ 「这么想自己的时候，心里是很闷的。」 ← 只描述用户的处境，不加戏
```

### 坑 3 · 同一个意思说两遍

| 项 | 内容 |
|---|---|
| **现象** | 「跟别人比这件事本身就不公平。」+「这种比法本来就不公平。」 |
| **根因** | 去重函数只用 2-gram 重叠率（阈值 0.34），两句话字数差得多，重叠率算不高 |
| **修复** | 增加**核心词级去重**：抽实词片段，共享 ≥3 个核心词判为重复 |
| **产品意义** | "看起来不重复"和"听起来不重复"是两件事，机器能判的是前者 |

### 坑 4 · 改完反而更冷

| 项 | 内容 |
|---|---|
| **现象** | v4 第一版把 witness 做成"只说一句"，结果三种不同处境都回同一句「不用说话，我陪着。」 |
| **根因** | 修"太啰嗦"时矫枉过正，把"在场"和"敷衍"搞混了 |
| **修复** | witness 改成两句结构（共振 + 在场），只有 9 分以上才退到单句 |
| **教训** | **"少说"和"不说"是两件事**。陪伴的极简不等于空白 |

## 六、方法论的通用部分（可直接用于任何陪伴类产品）

### 6.1 共振句的三条写作铁律

```
① 只描述 AI 自己的反应，不编造 AI 的经历
   ✅「听你说这个，我心里也沉了一下。」
   ❌「我昨天也失恋了，我懂。」（编造，且抢戏）

② 只引用用户已经说出口的事实
   ✅「当着人下不来台，那种感觉会留很久。」（用户说了"当着所有人"）
   ❌「那几秒钟，应该特别长。」（用户没提"几秒"）

③ 不评价用户的对错，只确认他的反应的合理性
   ✅「不服气是对的。」
   ❌「你不该这么想。」（评判）
```

### 6.2 验证句的作用：解除自我怀疑

用户难受的时候，第一个想说但没说出口的问题是：
**「我这样是不是太脆弱了？」**

不回答这个问题，后面说什么都是在评判。
这就是为什么正常人安慰朋友时会说「换我我也受不了」——那句话的功能是**解除羞耻**。

### 6.3 什么时候必须闭嘴

| 情况 | 为什么 |
|---|---|
| 情绪 ≥ 8 | 认知带宽被占满，读不进分析 |
| 用户说"不知道为什么" | 他刚说了他不知道，你还问为什么 |
| 用户说"算了" | 追问等于告诉他边界不算数 |
| 用户在猜别人心思 | 你猜不出来，硬猜是抢戏 |

## 七、落到真实产品：System Prompt 怎么写

四层模型不能只写在文档里，必须写进提示词。核心是三条：

```
1. 先确认感受，再谈内容
   对方说完一件事，先说他大概什么感受、这个反应为什么会发生，
   再决定要不要分析。

2. 分析最多一句，且必须建立在对方说过的事实上
   不要替他补全没说出口的场景。

3. 情绪越重，话越少
   对方如果处在崩溃边缘，只回一句"我在"，不要追问、不要分析。
```

完整版已更新到 `prompts/02_系统提示词_SystemPrompt_v1.md`。

## 七之五、多轮对话才暴露的问题（v6 记录）

> 上面那些坑是**单轮探针**跑出来的。这一轮换了方法：模拟四段完整对话（每段 4–6 轮），
> 结果又抓出六个问题，其中三个单轮永远测不出来。

### 6.1 短句被长度判断劫持

| 项 | 内容 |
|---|---|
| **现象** | 「烦死了」3 个字、愤怒 6 分 → 命中"极短输入"分支 → 只回「嗯。」 |
| **根因** | 判断顺序错了：先看长度（≤3 字），后看情绪 |
| **修复** | `(intent === 'minimal' \|\| len <= 3) && intensity < 5` |
| **产品意义** | **长度不等于信息量。**「烦死了」比一段 100 字的流水账情绪重得多 |

> 这条值得单独说：规则引擎最容易犯的错是**用一个便宜的信号（字数）代替一个贵的信号（情绪）**。
> 真实模型不会有这个问题，但人在设计兜底逻辑时会有。

### 6.2 共振句和归因对不上

| 项 | 内容 |
|---|---|
| **现象** | 「被领导当众点名」归因是 `public_humiliation`，共振句却取了 shame 池的第一条「这么想自己的时候，心里是很闷的。」 |
| **根因** | 共振池**只按情绪索引**，而情绪（shame）比痛点（当众下不来台）粗 |
| **修复** | 新增 `PAIN_RESONATE`，**优先按痛点取**，取不到才退回按情绪 |
| **面试怎么讲** | 「我发现同一个情绪下，不同的痛点要完全不同的话。被当众批评和自我否定，都是 shame，但一个要接'没处躲'，一个要接'别给自己定罪'。」 |

### 6.3 多样性不能牺牲准确性

| 项 | 内容 |
|---|---|
| **现象** | 为了"变化"，代码里写了 20% 概率改用情绪池 → 结果 20% 的场景共振错位 |
| **修复** | 删掉那个随机数。痛点已知就用痛点池，池里本来就有 3 条轮换 |
| **教训** | **"随机"是廉价的多样性。**真正的多样性来自"针对不同处境说不同的话"，不是把对的换成错的 |

### 6.4 愤怒 9 分被当成绝望

| 项 | 内容 |
|---|---|
| **现象** | 「我真的受不了了」→ anger 9 分 → 走 witness → 只回「今晚不用解决任何事。」 |
| **根因** | 策略选择里"≥9 分走 witness"没有排除愤怒 |
| **修复** | witness **只给绝望类情绪**；愤怒无论多高分都走 validate |
| **产品判断** | **绝望需要陪伴，愤怒需要站队。**两者在最高强度下依然不能合并 |

### 6.5 跨轮说同一句话

| 项 | 内容 |
|---|---|
| **现象** | 第 1 轮「还没过去，不代表你走不出来…」，第 2 轮几乎同一句又出现 |
| **根因** | 共振池和验证池是两个独立的池，`state.used` 只防同池重复 |
| **修复** | 增加 `state.recentLines`，跨池做 2-gram 比对 |

### 6.6 验证句复述了共振句

| 项 | 内容 |
|---|---|
| **现象** | 共振「反复落到同一个地方，是最耗人的。」+ 验证「反复落到同一个地方，确实最耗人。」→ 去重后只剩一句 |
| **根因** | 两句话义重复，写的时候没对照 |
| **修复** | 明确分工：**共振确认感受，验证解释"为什么这不是你的错"**，不许复述 |
| **通用规则** | 验证句必须提供**新的信息**，不能是共振句的同义改写 |

## 七之六、多轮对话的方法论：一句话检查表

连着聊四轮后，问自己这四个问题：

```
① 第 2 轮和第 1 轮，说的话有实质区别吗？（还是换了词的同一句）
② 它有没有记住第 1 轮说的那件事？（除了记忆库，还要有"话头上"的承接）
③ 用户情绪变重时，它的话变少了还是变多了？（应该是变少）
④ 用户说"算了"的时候，它追问了吗？（追问就是失职）
```

> **为什么必须多轮测**：
> 单轮测的是"这句话回得好不好"，多轮测的是"这个人会不会聊天"。
> 用户感受到的从来不是单条回复，是**一段关系的走势**。

## 八、面试怎么讲这段（可直接用）

> 「我的 Demo 有个问题被我自己抓到了：说得都对，但很冷。
>
> 我把这个问题拆开看，发现是结构问题，不是词表问题——
> 我的回复只做了四层情绪回应里的第四层（推论），
> 缺了命名、正常化、在场这三层。
>
> 于是它读起来像咨询师在给诊断，用户在听分析。
>
> 改的时候我踩了三个坑，都是跑真实语料跑出来的：
> 第一个是把愤怒判成'需要安抚'，回了一句'不用说话我陪着'——
> 那是让人闭嘴，比不改更糟；
> 第二个是编造用户没经历过的场景，'那几秒钟应该特别长'，
> 可用户根本没提几秒；
> 第三个是去重只算字符重叠，两句意思一样的话被保留了。
>
> 最后我定了一条规则：**共振句只能描述我自己的反应，和用户已经说出口的事实。**
> 这条规则我想了很久，因为它其实是陪伴产品的信任底线——
> 你可以说错话，但不能替用户编造他的生活。」

**为什么这段话有杀伤力：**
```
① 你自己发现了产品的缺陷（不是等人指出）
② 你能把"感觉问题"拆成结构问题（这是产品能力）
③ 你踩的坑有具体样子（证明真做了）
④ 你最后给了一条可复用的原则（有沉淀）
```

## 九、还没解决的部分（诚实清单）

| # | 问题 | 状态 |
|---|---|---|
| 1 | 共振池仍是有限模板，聊多轮会重复 | 规则引擎天花板；真实模型不会有这个问题 |
| 2 | 无法判断用户说的是真事还是试探 | 需要多轮上下文，单轮规则做不到 |

> 能说清"哪些是规则引擎的局限、哪些是产品设计的空白"的人，
