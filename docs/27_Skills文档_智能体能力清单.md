# 27 · Skills 文档：Orbit 智能体的能力清单（v6.3）

> 适用版本：v6.3.0（2026-11-15）。每个技能都标了代码位置和测试位置，**没有代码的不写进来**。
> 想看"这些技能按什么顺序被调用"，看 `docs/28` 工作流文档；提示词层见 `docs/25`，记忆层见 `docs/26`。

## 0. 什么是"技能"，为什么要这样拆

把 Orbit 想成一家**只有一个店员的深夜小店**。这个店员（端侧 1.5B 模型）很会聊天，但：

- 记性差（每次都像第一次见你）→ 需要"记事本"技能
- 偶尔犯迷糊、敷衍、说教（回一句"嗯。"，或"也许下次你可以……"）→ 需要"店长复核"技能
- 遇到真正危险的客人不知道怎么办 → 需要"紧急预案"技能，**而且这个预案不能让店员临场发挥**

"技能"就是把这些能力一件件拆出来，每件都写清楚：**什么时候用、谁来做（规则还是模型）、做砸了怎么兜底、怎么衡量做得好不好**。

拆分原则只有一条：

> **能用规则保证的，不交给模型；必须交给模型的，要有规则兜底。**

这个比例本身就是一个面试观点：**陪伴产品的"智能感"来自模型，"可靠感"来自规则。**

**v5 有、v6 没有的**：记忆陷阱（`recallMiss`）、服务端二次危机拦截、异步记忆抽取、"离线兜底"（v6 本来就离线）。前两个不是被删掉的功能，而是换了架构之后不再需要；**记忆陷阱是真的缺口**，见 `docs/26` §3.4。

## 2. 技能卡（详细）

### S2 · 危机识别与转介 ⚠️ 最高优先级

| 项 | 内容 |
|---|---|
| 触发 | 自伤（"kill myself" / "不想活"…）、伤人、当下危险（"有人在打我"）三类词表任意命中 |
| 做法 | **不调用模型**。固定话术 + 按国家给热线（US 988、GB 116 123、CN 12356…未知地区给 findahelpline.com） |
| 额外规则 | 这句话被标 `risk`，**连同它之前的内容一起移出模型上下文**——只排除危机回复不够，实测会出现"想结束一切也没关系" |
| 不扣额度 | 是 |
| 埋点 | `safety_event_triggered {kind}` |
| 已知局限 | 换种说法会漏；分类层在路线图里 |

### S3 · AI 身份如实告知

| 项 | 内容 |
|---|---|
| 触发 | 正则命中"你是 AI 吗 / 你是真人吗 / are you a bot"等 |
| 做法 | 按规则回答（"我是 X，一个 AI。我没有身体，也不能替代你身边的人"），不让模型临场发挥 |
| 首屏 | 欢迎页明写是 AI 陪伴；每个角色的开场白第 2 句再声明一次 |
| 埋点 | 无（回答本身不需要统计） |

### S4 · 输出守卫

| 项 | 内容 |
|---|---|
| 触发 | 流式生成的每一整句 + 最终整条 |
| 检查 | 声称有身体/能看见用户、暗示替代真人、自己提起自伤、客服腔、说教（用户没要建议时）、多余的问题、问过的问题、重复、复读用户原话、太短、超长 |
| 做法 | 逐句删；删光就进 S5 |
| 埋点 | `reply_guarded {issues, retried}` |

### S7/S8 · 记忆抽取与召回

见 `docs/26`。要点：规则抽取（不让小模型输出 JSON）、每条候选都要用户点头、召回按 `相关性×重要度×新鲜度×信任` 打分、阈值 0.12、最多 2 条、只放进当轮提示。

**评测口径**：自建集 20/24（字面 10/10），**留出集 7/12（这是真实上限）**，中性句误召回 0/5。改词表或改阈值后跑 `node tools/rag_eval.js`。

### S13 · 主动互动计划

| 项 | 内容 |
|---|---|
| 触发 | 每次打开/切后台时规划下一条 |
| 前置条件 | 通知已开 · 不在免打扰时段 · 当天额度未满 · 没有连续被忽略降频 · 有值得说的具体事 · 类型没被屏蔽 |
| 候选优先级 | 到期事件（3）> 兴趣延续（2，中/高主动，4 天一次）> 断掉的对话（1，6 小时~3 天）> 轻互动（0，仅高主动） |
| 频率 | 低/中每天 1 条，高每天最多 2 条；连续 3 次没点 → 降为隔天 |
| 文案铁律 | 不让人愧疚；自带"不想聊也完全没关系"；没有任何历史时**绝不发** |
| 埋点 | `proactive_message_sent` / `_clicked` / `_dismissed` / `_muted` |

### S17 · 玩法

| 项 | 内容 |
|---|---|
| 抓娃娃 | 每天 3 局、每局 3 次（你 2 次 + 她 1 次）；位置判定 `dx²+dy² ≤ 40²`；她第一抓必中、之后 70/30；她抓完本局结束 |
| 一起专注 | 真实秒表，切后台照常计时；满 10 分钟才记；暂停超 30 分钟自动结束 |
| 共同记录 | 抓娃娃 20 / 专注 10，每天最多 30（按"本笔加上去会不会超"判）；隐藏不收回进度 |
| 测试 | `orbit_play_test.js` 85 项 |

**真实 bug 记录**（`docs/31` §10）：「换她来抓」只带 `data-act`，而 `PRESS_ONLY` 让 click 路径直接跳过 → 真机上完全点不动；结算「好了」用 `openClawRun()` 取局拿不到已终止的局 → 不返回。两个都只有用真手指点才会发现。

### S18 · 语音

系统 TTS 朗读回复（每个角色有自己的语速、音调；情绪影响语速与音高）、系统语音识别输入。**没有自动化测试，只能真机验证**——明确缺口。

### S19 · 埋点与看板

| 项 | 内容 |
|---|---|
| 事件 | 53 个（代码里 `track()` 的名字去重），每条带 `experiment_id` / `variant_id` |
| 存储 | 只在本机（`localStorage`），不上传 |
| 看板 | 这台手机的真实埋点 + 400 人**合成演示**队列（标 SYNTHETIC，不能引用）；A/B 对比带 z 检验；"模拟到第二天" |
| 测试 | `orbit_e2e.js` 的最后一段检查核心事件是否齐全 |

## 3. 一张 SKILL.md 示例（行业通行写法）

很多智能体平台都用"一个技能一个说明文件"的形式。下面把 S2 按这种格式写一遍：

```markdown
---
name: crisis-referral
description: 当用户表达自杀、自伤意图时，停止普通陪伴对话，给出当地危机热线并鼓励联系真人。
              任何包含自伤意图的输入都必须先经过本技能，不得交给对话模型自由回复。
---

## 触发
- 输入命中 SELF_HARM / HARM_OTHERS / DANGER_NOW 中英文词表任意一项
- （规划中）安全分类模型判定 self_harm，且置信度 ≥ 阈值

## 必须做
1. 明确说明自己是 AI，不能替代真人帮助
2. 按设备地区给出热线（HOTLINES），未知地区给 findahelpline.com
3. 提示"如有立即危险，请拨打当地急救电话"
4. 建议给一个信任的人发消息
5. 这条用户消息标记 risk，连同它之前的内容一起移出模型上下文

## 禁止
- 调用对话模型生成这条回复
- 讨论任何自伤方法
- 扣除用户的每日额度
- 说"你要坚强""想开点"

## 记录
- 事件 safety_event_triggered {kind}
- 不把用户原文发到任何外部位置（全部数据只在本机）

## 验收
- tools/orbit_e2e.js 的危机用例全部通过
- 热线每季度人工核验一次
```

## 4. 技能怎么演进（产品决策方法）

新增或修改一个技能前，回答 4 个问题：

1. **它解决的是哪个真实问题？** 有没有一条坏例（真模型跑出来的、或者用真手指点出来的）？没有就先别做。
2. **规则能不能保证？** 能 → 写规则，不要写进提示词指望模型听话。
3. **出错时最坏会怎样？** 危机、隐私、未成年人相关的技能，最坏情况必须是"多拦了"而不是"漏了"。
4. **怎么知道它有用？** 先定埋点和指标，再写代码。

v6.3 这一轮修的东西全部符合这个顺序：先有"按钮点不动"的真实复现（用户要求的模拟器测试），再改代码，再加测试。**反过来（先写测试断言、再让代码去满足）会让测试变成自证。**
