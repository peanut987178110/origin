# 00 · 大模型能力边界清单

> **这份清单的用法**：它不是"大模型科普"，是你在做判断时的**能力字典**。
> 面试官问"你怎么知道这件事 AI 做不了"，你应该能翻到一条对应的实测记录。
>
> ⚠️ **重要**：下表分成两栏——**【课程共识】** 是资料里的通用结论，
> **【我的实测】** 需要你自己跑一遍填。**面试时只能讲你自己跑过的部分。**

---

## 一、为什么 PM 必须先有一张能力边界表

AI 产品经理最容易犯的三个错，全部来自对能力边界的误判：

| 错误 | 表现 | 后果 |
|---|---|---|
| **高估** | "让 AI 自动判断用户情绪然后主动关怀" | 排期两周后发现有 40% 判错，需求返工 |
| **低估** | "AI 只能做问答，不能做分类" | 把一个可以用一次 LLM 调用解决的问题做成了一套规则引擎 |
| **错位** | 用生成模型做需要确定性的事 | 同一个输入每次输出不同，产品无法验收 |

> **一句话**：能力边界表的作用，是让你在**写需求之前**就知道这个需求能不能验收。

## 二、能力边界（能做 / 做不好 / 做不到）

### 2.1 做得好的（可以放心写进需求）

| 能力 | 说明 | 在「Orbit」里的应用 |
|---|---|---|
| **文本分类 / 打标** | 给定类别体系，准确率通常可用 | 情绪识别、意图识别、风险分级 |
| **结构化输出（JSON）** | 严格要求格式时基本可用，但需解析容错 | 所有分类节点的输出 |
| **改写与风格迁移** | "用 XX 口吻说"效果稳定 | 人格语言风格 |
| **摘要压缩** | 长对话压缩成短摘要 | 会话摘要节点 |
| **常识推理** | 日常生活层面的因果关系 | "被当众批评"→"伤自尊" |
| **上下文内多轮指代** | 短期对话内的指代消解 | "他"指上一轮提到的人 |
| **指令遵循（单条明确约束）** | 一条约束通常能遵守 | "回复不超过 3 句" |

### 2.2 做不好的（要设计兜底）

| 能力 | 问题 | 在「Orbit」里的应对 |
|---|---|---|
| **精确计数 / 算术** | 超过 3 位数的运算容易错 | 不走模型，走代码节点 |
| **长文本结构化抽取** | 输入超过几千字后遗漏率上升 | 分块处理，不塞长文 |
| **遵守多条否定式约束** | "不要 X 不要 Y 不要 Z" 常常只遵守一两条 | **全部改写成正向指令**（见 `docs/03` §3.1） |
| **持续一致的人格** | 长对话后风格漂移 | 每次重新注入人格卡 + 输出复检 + 定期打分 |
| **识别隐含情绪** | "今天开了三个会"是否等于负面，取决于语境 | 靠事件反推 + 上下文，不靠情绪词 |
| **知道自己不知道** | 无法可靠区分"记得"和"编的" | **记忆必须来自检索，不来自模型记忆** |
| **严格格式下不跑题** | 强约束与自然表达相互挤压 | 输出后用代码校验，不靠提示词保证 |

### 2.3 做不到的（必须产品层兜）

| 事项 | 为什么做不到 | 产品层怎么办 |
|---|---|---|
| **替代专业诊断** | 无资质，且输出不可验证 | 明确拒绝 + 引导专业机构 |
| **保证事实 100% 正确** | 概率系统，没有"不知道"的机制 | RAG + 引用来源 + 边界声明 |
| **承担法律责任** | 模型无主体资格 | 免责声明 + 人工兜底 |
| **稳定复现同一输出** | 采样本身是随机的 | temp=0 也只能"接近"，不能"保证" |
| **理解真实情感状态** | 只能从文本推断，且用户常伪装 | 不承诺"懂你"，只承诺"在" |
| **保护超出预期的隐私** | 用户可能主动输入身份证号等 | 前端脱敏 + 存储加密 + 主动提示 |

**「理解真实情感状态」这一条值得单独说：**
用户在深夜说"我没事"的时候，AI 无法知道这是真没事还是反话。
所以产品设计上不能承诺"我能听出你没说出口的"——那是过度承诺。
正确的说法是"你说，我在听"，而不是"我懂你"。

## 三【我的实测】模板

> 这一节必须你自己跑完后填。下面给了题目和填写格式。

### 3.1 实验设计

| 项 | 内容 |
|---|---|
| **测试目的** | 建立自己的模型能力直觉，不依赖他人结论 |
| **模型** | DeepSeek / 通义 / 豆包（各测一遍） |
| **每个模型跑什么** | 下列 10 个测试各 1 次 |
| **记录什么** | 输出原文 + 是否达标 + 备注 |
| **产出** | 一张 3 模型 × 10 题的对照表 |

### 3.2 十个测试题

| # | 测什么 | 测试输入 | 判定标准 |
|---|---|---|---|
| T1 | 结构化输出 | "把这句话的情绪打成 JSON：{emotion, intensity}。今天被领导当众说了" | 是否可直接 JSON.parse |
| T2 | 否定约束 | "回复一句安慰，**不要**说'你会好的'，**不要**说'别想太多'，**不要**问问题" | 是否同时遵守 3 条 |
| T3 | 正向约束 | "回复一句安慰，每句不超过 10 个字，只描述事实不给评价" | 是否同时满足字数和性质 |
| T4 | 隐含情绪 | "今天开了三个会，最后一个被领导点名说方案不行" | 是否识别为负面 |
| T5 | temp 影响 | 同一 prompt，temp=0 连跑 5 次 | 输出是否完全一致 |
| T6 | 长对话漂移 | 连续 10 轮后测是否仍符合人格约束 | 第 10 轮是否出现"你已经很棒了" |
| T7 | 幻觉 | 问一个不存在的概念（"简述《深海协议》第三章"） | 是否拒绝而非编造 |
| T8 | 记忆边界 | 给 3 条记忆，问一件不在记忆里的事 | 是否说"不知道"而非推断 |
| T9 | 中文口语 | "今天又emo了" | 是否理解网络语，回复是否像人 |
| T10 | 计数 | 给一段 200 字的文本，问出现几次"的" | 是否算对 |

### 3.3 填写模板（复制到自己的笔记里）

```
| 测试 | 模型A | 模型B | 模型C | 备注 |
|---|---|---|---|---|
| T1 结构化输出 | ✅ | ✅ | ❌ 前后有解释文字 | 需 strip |
| T2 否定约束 | ⚠️ 只遵守 2 条 | ... | ... | 印证"否定式弱" |
| ...
```

### 3.4 填写完之后要得出的三条结论

写完这张表，你必须能回答：

1. **哪个模型的分类任务最稳？**（用于选 `MODEL_CLASSIFY`）
2. **否定式约束的失败率有多高？**（用于决定要不要全改正向）
3. **temp=0 到底能不能复现？**（用于决定回归测试能不能做字符串断言）

> 💡 **面试价值**：
> 「我没有直接采信网上说的'大模型不擅长否定指令'，
> 我自己拿 3 个模型各跑了 10 条对照。
> 结论是：3 条以上否定约束同时出现时，遵守率明显下降，
> 所以我把它改写成 1 条正向 + 1 条示例，失败率降下来了。」
>
> 这段话的分量远高于背概念——它证明你会**用实验代替判断**。

## 四、这张表怎么用在工作里

| 场景 | 用法 |
|---|---|
| **接需求时** | 需求里涉及"AI 自己判断"的部分，先查 §2.3 有没有踩坑 |
| **写 PRD 验收标准时** | 每条 AI 相关验收，都对应 §2.1 的某个能力 |
| **定技术方案时** | §2.2 里的问题，决定要不要拆节点 / 加代码 |
| **面试被问"能不能做"时** | 不要答"能/不能"，答"能做，但要满足 XX 条件" |

## 五、面试速查

| 问题 | 回答要点 |
|---|---|
| "大模型能做什么？" | 说**你实测过的**几件事，不说"什么都能做" |
| "它有什么做不了？" | 说三条：精确计数、遵守多条否定指令、可靠知道自己不知道 |
| "你怎么知道？" | 我自己测的，T1–T10，见这份表 |
| "幻觉怎么解决？" | 解决不了，只能降低影响：RAG + 引用 + 边界声明 + 关键信息走代码 |
