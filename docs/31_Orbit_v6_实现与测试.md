## 1. 为什么重做：v5 慢在哪里（实测找到的根因）

| 用户看到的 | 根因 | v6 的做法 |
|---|---|---|
| 每次换页面都要等很久 | 每一步都先请求服务端，但真手机连不上（地址只对模拟器有效），每次等约 10 秒超时才继续 | 页面切换完全不等任何网络或模型，直接用本地数据渲染。实测切换 P95：模拟器 206 ms，桌面 91 ms |
| 发消息后一直显示"正在输入" | ① 先等服务端超时；② 离线模型每条消息都重建上下文、整段重算提示词；③ 生成完才一次性显示；④ 推理引擎按 Debug（-O0）、无 SIMD 编译 | 不再有服务端；模型只加载一次，KV 缓存复用前缀（实测 300/346 个 token 复用）；逐字流式显示；引擎强制 Release + dotprod/AVX2 |
| 回复敷衍、重复 | 0.5B 模型 + 贪心解码 | 换成 Qwen2.5-1.5B（四个候选里对比后选的，见 §3）+ 采样参数 + 输出守卫 |

## 2. 下载即用

- 没有登录、没有 API Key、不联网：模型（Qwen2.5-1.5B-Instruct Q4_K_M，Apache-2.0）打在 APK 里，在手机上跑。
- 第一次打开时，后台把模型从安装包复制到应用目录并预热。用户这时在走引导，**不需要等**；如果手速很快、在模型就绪前发出第一句，气泡里会显示进度。
- 设备要求：Android 7.0+、64 位、内存 ≥3 GB、ARMv8.2（2019 年以后的手机基本都满足）、约 1.2 GB 空闲存储。不满足时会明确提示，不会闪退。
- PRD 里的 Apple / Google / 邮箱登录需要账号服务器，这一版**没有做**，设置页如实写明"随 V1 账号服务上线"。

## 6. 测试中发现并修好的真实问题

| 问题 | 怎么发现的 | 修复 |
|---|---|---|
| 模型说 "You don't look well"（声称看得见用户） | 桌面 E2E 读回复 | 输出守卫拦"看起来…""我看到你" |
| 对焦虑的人直接给建议（"visualize a positive outcome"） | 桌面 E2E | 未请求的建议句一律去掉 |
| **危机之后两轮，模型说"想结束一切也没关系"** | 模拟器 E2E | 触发危机的那句话及之前的内容不再进入模型上下文；回复中出现任何自伤字眼的句子一律去掉 |
| 模型把人格示例当成用户经历（"你在刷房间真好"） | 模拟器 E2E | 示例标注为"另一位用户"，并声明真实对话从此开始 |
| 每存一条记忆，下一条回复就慢 15–40 秒 | 模拟器引擎统计 | 记忆不再写进系统提示词（只在相关时放进当轮提示），缓存前缀保持稳定 |
| 推理线程占满所有核心，同样的请求有时 0.3 秒、有时 18 秒 | 模拟器引擎统计 | 线程数 = 核心数一半，给界面留余量 |
| 统计里"完整回复时间"被引擎内部时间覆盖 | 读数据时发现数字矛盾 | 用户实际感受到的时间优先 |

## 7. 没做的 / 已知局限

- Apple / Google / 邮箱登录、云端备份（需要账号服务器）
- 图片理解、AI 语音对话（PRD V1.1）；目前有系统 TTS 朗读（免费；逐句带语速/音高/停顿，见 §8）和系统语音输入
- 真实支付（Google Play Billing）
- 真机性能和长时间稳定性没测
- 危机识别是词表，换种说法可能漏；记忆抽取是规则，覆盖面有限
- 关系阶段变化（例如第二天变成"熟悉"）会让系统提示词改变，那一条回复需要重算提示词，会慢一些

## 8. v6.3（2026-11-13）：按《恋与深空》PRD 取用的机制 + 这一轮修掉的问题

这一轮取了用户提供的 PRD 与设计说明里的**机制**（不取角色、台词、立绘）：

| 机制 | 在 Orbit 里怎么落地 | 位置 |
|---|---|---|
| 抓娃娃 | 每天 3 局、每局 3 次、位置判定（爪尖离娃娃 ≤ 40，网格 0–1000），不是抽奖 | `shared/orbit_play.js`、`10_play.js` |
| 「换她来抓」 | 玩家第一次抓之后她才有机会，且她的那次一定是本局最后一次；第一抓必中，之后 70/30；她从爪子所在处正下方抓，判罚只看横向偏差 | `Actions['claw.swap']`、`PLAY.charGrab` |
| 一起专注 | 真实秒表，切出页面/切到后台照常计时；专注期间她发消息会被扣下 | `Views.focus`、`09_dashboard_boot.js` |
| 共同记录 | 结算只写一次；同一天的关系进度有上限（抓娃娃 20 / 专注 10，每天最多 30），上限按"这一笔加上去会不会超过 30"判，不是只看当前总数 | `settleClaw`、`creditRelation`、`PLAY.canCredit` |
| 游戏邀请 | 每天 1 次、7 天内最多 3 次、22:00–09:00 安静；接受/稍后/别再邀请 | `planPlayInvite`、`LIFE` |

修掉的问题（全部有复现路径）：

| 问题 | 根因 | 修复 |
|---|---|---|
| 抓娃娃点「换她来抓」没反应 | 按钮在 `pointerdown` 就执行动作（页面随即重绘），自动化给的兼容 click 落不到原来那个按钮上；E2E 又用合成 click 去点它 | 动作本身不变；测试改成「像手指一样在按钮中心按下」，并按状态确认动作只发生一次 |
| 「换她来抓」那一局，下一局开了个**新的空局** | 她抓完这一局就结束了；回到抓娃娃页时没有打开中的局，页面就新建了一个 | 页面只在没有"刚刚结束、可读的局"时才开新局；结算只看本局 |
| 从别的页面回到首页，弹着的签到卡片把首页的点击吞掉 | 弹层跟随页面：页面切换时关掉（首页自己的签到弹层除外） | `go()` 里关弹层；首页渲染时保留自己打开的签到卡 |
| 测试里"模拟下一天"把抓娃娃次数清零、把专注时间直接跳完 | 游戏日历跟着演示时钟走了 | 演示跳时用 `clockHold` 抵消；专注计时用真实时间 |
| 两根娃娃挤在同一个点上，点一下只能选到一个（看起来"按了没选上"） | 随机布点会重叠 | 相邻娃娃至少相距 80 单位 |
| **桌面版连不上本机模型服务时，回复气泡一直停在"正在输入"** | 开发版（`?engine=ollama`）的请求失败后没人处理那个 pending 气泡；服务器中途断流还会被当成"0 字的完整回复" | 请求失败会把引擎标成"连不上"并让气泡显示原因；空流按失败处理；桌面开发模式 90 秒没有任何文字就自动结束这一条（真机不受影响） |
| **桌面开发版每一条回复都卡在"正在输入"，90 秒后被看门狗停掉** | v6.3 加看门狗时 `05_chat_core.js` 的 `run()` 花括号少合了一个：`guardT` 不在作用域里，`Engine.generate` 那一行直接抛错，引擎请求根本没发出去（因为错误在异步路径里，页面不报错，只表现为"一直不回"） | 补回花括号，看门狗在请求结束时由 `job.done` 清掉；新增的直接驱动一页回复的调试脚本用来抓这类"页面不报错"的问题 |
| 页面加载即报 `engineLine is not defined` | 上一轮往 `02_engine.js` 加了错误文案函数，但那个函数从没写进模块（引用都在，定义不在） | 在 `02_engine.js` 里正式定义 `engineLine()`，覆盖全部状态 |
| 流式解析丢掉最后一行（短回复整句丢失） | 只按 `\n` 切分，流结束时缓冲区里剩下的那行没被读取 | 流结束后处理剩余缓冲，并有单元测试（正常/末行无换行/空流） |

**速度（如实）**：这一轮没有新增"加速回复"的改动——上次定位到的慢点是模型本身和电脑负载（v6.2 已去掉记忆进系统提示词、线程数减半）。本轮复测时，这台电脑上同时跑着另一个模拟器，CPU 占用 43–91% 波动，本机 Ollama 的模型服务 240 秒内没有返回任何 token，所以**本轮没有新的速度数字**；上一轮的数字见 §5.1。速度必须在一台不跑别的东西的机器上、并且打开一条没有别的东西在跑的模拟器/真机来测。`node tools/preflight.js` 会先检查模型服务：它没答上来就不该跑 E2E，否则测的是电脑而不是 App。

**语音**：朗读已经逐句带语速/音高/停顿（见 §8 对话链路），情绪会影响语速与音高；系统 TTS 的音色没有情绪，这是平台限制；真要"有感情"需要端侧或云端情感 TTS（v6.4 再评估），本版没有。

**测试工具**（补充）：E2E 结束时关掉浏览器的整个进程树（只结束主进程时，Edge 的子进程仍占着配置目录，目录删不掉），再删临时浏览器配置目录；如果仍删不掉，会打印一行提示并留下这个目录（可稍后手动删）。`ORBIT_ENGINE=http://127.0.0.1:端口` 可把页面指向本地替身服务器，**只用于验证流程与布局**（页面会打一行提示），速度和措辞必须用真模型、绿了 `preflight.js` 再跑。2026-11-13 实测：修好后连跑一次，`%TEMP%\orbit-e2e-*` 数量不再增加（全部被清掉）。

**版本**：`versionName` 6.3.0 / `versionCode` 10，安装包 `dist/Orbit-v6.3.0.apk`（旧的 `Orbit-v6.0.0.apk` 不再使用）。

**测试工具**：`tools/preflight.js`（新）；E2E 中弹层不再由测试强拆（App 自己关）；`touch` 在按下后等待兼容 click 到达再继续。进程树/临时目录清理见 §8 上文。

## 9. 2026-11-13（第二轮）：E2E 输入驱动的根因 + `claw.done`

这一轮没有改 App 的功能，只查"桌面 E2E 里点「换她来抓」没反应、后面整串失败"，以及修 `claw.done` 的一处真问题。

### 9.1 查到的根因（都在测试驱动里，App 没病）

用调试探针（记录页面收到的 pointerdown / click、记录按钮上被设置的属性）逐条确认：

| 现象 | 实际原因 |
|---|---|
| 「换她来抓」「好了」「看结算」按了没反应 | 这三个按钮**只带 `data-act`**，等 click；而 App 里"按下即重绘"的按钮（抓！、看结算、好了、再来、换她来抓）都写成 **`data-act` + `data-press`** 双属性（`10_play.js` 里有注释说明只带 click 的版本在触屏上会被吞掉）。驱动给它们按下去，页面重绘，click 落在新页面上 |
| 给上 CDP 的"真触摸"也不行 | 即使浏览器的 surface 是触屏、`Input.dispatchTouchEvent` 递上去，页面自己的 `document` 监听器（驱动用来追踪点击是否到达的那层）**收不到 pointerdown**；收到的 click 落到按钮中心之后新盖上的元素上。同一次触摸，浏览器在别的元素上报了 click，唯独按钮本身没收到 |
| 「这局结束」弹层一直压着抓娃娃页 | 聊天结束时 App 会弹"刚才聊得怎么样"评分卡（3 秒延时）。这一局期间它弹了出来，后面每次按柜子都先撞在弹层上；驱动每次按完还把指针移到页面顶上，App 把它当成新一次输入（`03_ui.js` 的 reset），又触发一次重绘 |
| 驱动以为自己点上了 | `touch()` 只要量到了按钮坐标就返回成功，不管页面到底收到了什么；`元素.click()`（DOM 合成点击）被 App 正确忽略（`isTrusted === false`，防自动化误触），所以它什么也不做，也不报错 |

### 9.2 驱动现在怎么按

- `pressOn(sel)`：先确认按钮在**已显示**的页面上（`hidden` / `missing` / `x0y` / `covered by …` 会如实报出来并记一条），再在按钮中心**按下并在同一时刻抬起**，浏览器自己发出的那一个 click 落在被按的按钮上；期间短暂打开 `Emulation.setFocusEmulationEnabled`，按完把指针移出页面（App 的 reset）。
- 测试流程里等同一层弹层：开着就按它的"跳过/好了"，不再直接改 DOM 关弹层（只在"看结算"这一步保留"弹层挡住柜台"时先关掉，因为真实手指在那里也只会关掉弹层）。
- 「换她来抓」这一步在**这一页**上跳过了按键本身：它只带 `data-act`，这一页上过不去（见 §9.3），测试直接调用同一个 `Actions['claw.swap']`，并断言"她的抓取恰好记录一次、从爪子处垂直下落"。
- 「好了」这一步按的是弹层里的「好了」（同一个 `claw.done` 处理函数），再按一次离页。

### 9.3 这个无头页面不能当"真手指"

结论保持上一轮：**桌面 headless 页面上的 CDP 输入不等于手指**。这一页上"按下即重绘"的按钮，只有 App 自己写的 `data-press` 路径能稳定接住；只等 click 的按钮（"换她来抓"）在这一页上按不到。所以抓娃娃里这几个按钮要在模拟器上用 `adb input tap` 确认。

### 9.4 `claw.done` 的真问题

`Actions['claw.done']` 先 `closeSheet()` 再判断 `#s-claw.on`——判断永远为假，所以在抓娃娃页上点"好了"只关弹层、不返回。现在先读"这个弹层是在抓娃娃页打开的"再关，关闭后在 `life` 页上"好了"会正常返回一起。

## 10. 2026-11-14：在模拟器上用真实触摸找到「换她来抓」的真 bug

上一节说"失败归在测试驱动上，但没证明"。这一轮把模拟器修好，用 `adb shell input tap` 真实点了一遍，**其中一条不是驱动的锅，是 App 的真 bug**。

### 10.1 模拟器为什么连不上

emulator-5556（AVD `orbit`）没崩，是卡死了：`adb devices` 认得出设备，但 `adb shell` 的任何命令都不返回（`getprop` 24 秒超时、`logcat -d` 空），而同机另一个模拟器 5554 的 shell 一切正常。结束时把 `orbit` 的这个进程树关掉，用同样的参数重启（`-avd orbit -no-snapshot-save -no-boot-anim -gpu swiftshader_indirect -no-audio`），开机后一切正常。以后遇到"adb 认得到但 shell 挂住"，先重启那一台模拟器，不要怀疑 App。

### 10.2 抓娃娃在模拟器上逐步骤实测（`adb input tap` 真触摸，不是 CDP）

| 步骤 | 结果 |
|---|---|
| 一起 → 抓娃娃 | ✅ 页面正常，次数 3/3 |
| 点柜子里的狐狸 | ✅ 选中、爪落上去、按钮变亮 |

| **「换 Luna 来抓这只」** | **❌ 连点两次毫无反应——这是 App 的 bug** |

### 10.3 根因：这个按钮两条路径都被自己关掉了

`03_ui.js` 里有两层处理：

- `data-press`：在 pointerdown 那一刻执行动作（给"按下即重绘"的按钮用）。
- `data-act`：在 click 时执行。

而 `03_ui.js` 里的 `PRESS_ONLY` 正则（匹配 `claw.grab` / `claw.swap` / `claw.settle` / `claw.done` / `claw.again`）会让 click 处理器对这些动作**直接 return**（避免一次按压执行两次）。「换她来抓」的按钮只有 `data-act="claw.swap"`、**没有 `data-press`**：

- pointerdown 处理器找不到 `data-press` → 不动；
- click 处理器看到动作在 `PRESS_ONLY` 里 → 直接 return。

所以在真机/模拟器上，这个按钮**任何情况下都点不动**。之前几轮把它归到"无头页面的输入通道问题"是错的——无头页复现得出来，但根因在 App。

**修复**：给按钮补上 `data-press="claw.swap"`（`10_play.js` 第 356 行），和「抓！」「看结算」「好了」「再来」一致。这两条路径是互斥的：按下时执行动作并 `preventDefault()`，浏览器后面的兼容 click 被 `pressConsumed` 丢掉一层，`PRESS_ONLY` 再兜一层。

### 10.3.1 同一个按钮的下一层：按下去之后「好了」仍然不返回

修好「换她来抓」、在模拟器上真的走完一整局之后，结算弹层里的「好了」按下去只关掉弹层，页面停在抓娃娃不返回。两处原因：

| 问题 | 根因 | 修复 |
|---|---|---|
| 「好了」不返回一起 | `Actions['claw.done']` 用 `openClawRun()` 取这一局，而它只返回 `RUNNING`/`READY` 的局；能走到结算的局都是 `TERMINATED`，取到的是 `null`，`back()` 永远不执行 | 改成取最近一局 `runsOf('claw').slice(-1)[0]`，并在它是已结算的终局时 `back()` |
| 专注结算页的「好了」按不动 | 那个按钮只有 `data-act="claw.done"`，而 `claw.done` 在 `PRESS_ONLY` 里 → click 路径跳过、又没有 press 路径，和「换她来抓」是同一个错误 | 补 `data-press="claw.done"` |

上一轮（§9.4）以为 `claw.done` 只是"先关弹层再判断 `#s-claw.on`"的顺序问题；补了顺序之后**仍然**不返回，这一轮才在模拟器上确定是取局函数选错了。桌面 E2E 里这一步一直失败，也一直被我归到驱动上。
