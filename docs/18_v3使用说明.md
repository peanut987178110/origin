# 18 · 潮汐 v3 使用说明（手机直连大模型）

> **2026-11-15 清理说明**：本文提到的 `prompts/`、`workflow/`、`evalset/`、`demo/`、`server/`、`analytics/`、`shared/tide_core.js` 是 v5 服务端版的内容，已从仓库移除（保留在学习方法里作对照）。v6 运行中的对应物：提示词 `shared/orbit_mind.js`、人格 `shared/orbit_personas.js`、记忆 `shared/orbit_memory.js`、玩法 `shared/orbit_play.js`；测试见 `docs/31` §10。

## 二、第一次使用（3 分钟）

### 1. 拿一个 API Key

推荐 **DeepSeek**：中文好、便宜、注册简单。

```
打开 platform.deepseek.com → 注册 → 实名 → 左侧「API keys」→ 创建
→ 复制出来那串 sk-xxxxxxxx（只显示一次，存好）
```

> 新用户一般有免费额度，充 10 元能聊很久。
> 陪伴场景每轮对话大约几百到一千 token，10 元通常能撑上千轮。

其他服务商见 `docs/20`，都有免费额度可以先用。

### 2. 在 App 里填上

```
打开潮汐
  → 注册（用户名 + 密码，只存这台手机）
  → 选陪伴者（12 个角色，按你现在的状态挑）
  → 选头像、调语速音调（可以点「试听一句」）
  → 连接大模型：选 DeepSeek → 接口地址和模型名已经填好了
     → 把 API Key 粘进去（格式 sk-...，不要带空格）
     → 点「保存并测试连接」
     → 看到「连接成功 ✓」→ 开始聊天
```

**一般只需要粘贴 Key**，地址和模型名都是预填的。
连不上想跳过也行，点「先跳过」，之后在聊天页右上角 ⚙ 里再配。

### 3. 开始聊

```
打字 → 右下角 ↑ 发送
点 🎙 说话 → 识别完自动发送
回复会一个字一个字流出来，开了「自动朗读」还会念出来
```

| 功能 | 实现 | 位置 |

| 对话持久化 | 最近 60 条存本机，重启不丢 | 自动 |

| 记忆陷阱硬规则 | 问「你还记得…」而记忆里没有 → 直接说记不得，**不编造** | 自动 |
| 敷衍回复复检 | 回复只剩「嗯。」→ 自动重生成，最多两次 | 自动 |
| 清空对话 | — | 设置 |

### 12 个角色（按"你现在是什么状态"分组，不是按性格形容词）

| 分组 | 角色 |
|---|---|
| 深夜睡不着 | 潮汐（安静）、小满（温柔） |
| 上班的人 | 阿岸（护短）、老周（过来人） |
| 学生 / 备考 | 小鱼（同龄人）、木老师（耐心） |
| 感情里受伤 | 晚晚（闺蜜）、阿野（哥们） |
| 一个人生活 | 奶奶（慈祥）、阿白（小猫） |
| 只想轻松聊聊 | 豆豆（开心果）、凌（理性） |

> 设计理由：用户选角色时想的是「我现在需要什么」，
> 不是「我喜欢温柔还是直率」。按人群分组比按形容词分组更容易选。
> 详见 `docs/19`。

## 四、架构（面试讲这张图）

```
┌──────────────── 手机 APK ────────────────┐
│  WebView 页面（src/app/index.html）        │
│   · 登录 / 选角色 / 设置 / 聊天 UI          │
│   · buildSystemPrompt() 人格提示词           │
│   · 危机词表 / 记忆陷阱 / 敷衍复检（先于模型）│
│         │ JSON 字符串                       │
│  LlmBridge.kt ──► LlmClient.kt             │
│    · 从 Keystore 取 Key 加请求头             │
│    · 逐行读 SSE，字一个个回传页面            │
│  KeyStore.kt ──► EncryptedSharedPreferences │
│  VoiceBridge.kt ──► 系统 TTS / 语音识别      │
└───────────────┬───────────────────────────┘
                │ HTTPS（公网只允许 https）
                ▼
   用户自己选的模型服务商
   DeepSeek / 通义 / Kimi / 智谱 / 豆包 / …
   或局域网里的 Ollama

   潮汐没有服务器：账号、对话、记忆只存本机
```

**五个设计取舍：**

1. **为什么用原生桥发请求，不让页面直接 fetch**
   WebView 跨域 + 页面拿不到 Key 明文。原生层发请求，Key 不出现在 JS 里，还能逐行读流。

2. **为什么只做一套协议**
   国内主流厂商都兼容 OpenAI 的 `POST {base}/chat/completions` + SSE。
   换服务商 = 换地址 + Key + 模型名，代码不改。

3. **为什么 Key 只进不出**
   页面能存、能问有没有、能看打码，但拿不到明文。页面被注入脚本也偷不走。

4. **为什么危机和记忆陷阱不走模型**
   这是"路由"，不是"判断"。提示词管不住小模型——实测 3B 模型在记忆为空时仍会编造。
   命中规则就本地固定回复，不给模型犯错的机会。

5. **为什么 http 只允许局域网**
   情绪对话是最敏感的数据。公网必须 https，页面和原生层双重校验。

## 六、这一轮修掉的真问题（都是跑出来的）

| # | 问题 | 后果 | 修法 |
|---|---|---|---|
| 1 | 页面把**对象**传给原生桥 | Kotlin 收到 `"[object Object]"`，手机上永远请求失败 | `JSON.stringify` |
| 2 | 网络配置按"网段"写域名 | Android 只认主机名，`10.10.1.52` 不匹配 `10.0.0.0`，明文被拦 | 配置放开 + 代码做私有 IP 校验 |
| 3 | Ollama 只听 127.0.0.1 | 手机连不进来 | `OLLAMA_HOST=0.0.0.0:11434` |
| 4 | 语音结束/出错回调没定义 | 麦克风按钮一直红着 | 补 `__tideSpeechEnd/__tideSpeechError` |
| 5 | 「您好」→「我在。」「面试过了」→「嗯。」 | 用户截图里的敷衍 | 提示词补「打招呼」「好消息」规则 |
| 6 | `<queries>` 放进了 `<application>` | APK 编译失败 | 移到 `<manifest>` 下 |
| 7 | 尝试加 Few-shot 示例 | 3B 模型把示例原句搬到无关场景 | **撤回**。小模型上示例是负收益 |
| 8 | 源码改了但没重新打包 | **dist 里的 APK 少了「记忆陷阱硬规则」** | `selftest.py` T9 加构建新鲜度检查；本次已重新出包 |
| 9 | 页面缺 `<!DOCTYPE html>` | WebView 进入怪异模式，盒模型可能异常 | 补上 |
| 10 | `verify_app.js` 把 `forgetKey(` 当成 `getKey(` | 自检误报，真正的回归信号被淹没 | 改用前置断言 `(?<![A-Za-z])getKey` |

第 7 条值得在面试里讲：
**「加示例效果更好」是常识，但在 3B 模型上实测是负收益——我用评测脚本发现的，所以撤回了。**
这就是评测集的价值。

第 8 条更值得讲：
**「改了源码却忘了重新打包」是最隐蔽的一类 bug**——测试全绿，用户手上的却是旧版本。
所以我给自检脚本加了一条"构建产物新鲜度"检查：比对源码与 `assets/` 的关键符号，缺就报错。

## 七、已知局限（诚实清单）

| 局限 | 原因 | 改进方向 |
|---|---|---|
| 换手机账号就没了 | 没有服务器 | 加后端 + 云同步（隐私方案要重新设计） |
| 语音音色取决于手机 | 用的是系统 TTS | 接云语音（火山/阿里）音质更好但收费 |
| 危机识别靠词表 | 隐晦但不在词表里的说法会漏到模型 | 加一层 LLM 安全分类（`prompts/05`），词表做加速器 |
| 记忆只记事实，不记语气 | 每 4 轮提炼一次，条数上限 8 | 记忆分「事实 / 情绪模式」两层 |
| 无痕模式没做 | 多人共用一个账号时会看到历史 | 加「临时会话」，退出不落盘 |
| 单轮回复上限 400 token | 陪伴场景不需要长文 | 情绪重的场景可以放宽 |
