# 12 · 合规与危机干预 SOP

> 这份文档是产品的**生死线**，不是"补充说明"。
>
> 情绪陪伴 + 危机话题 + 未成年人，是监管最敏感的三个交集。
> 现有材料只有一句"识别后功能降级"，这在实际运营中是不够的——
> **真要出事的时候，你需要的是流程，不是提示词。**
>
> ⚠️ 本文档为产品视角的通用框架，**不构成法律意见**。
> 上线前必须由公司法务审核，并对照最新监管要求。

---

## 一、为什么这类产品的合规风险特别高

| 风险来源 | 说明 |
|---|---|
| **用户处于脆弱状态** | 深夜、情绪低谷、可能抑郁——这类用户的决策能力弱于常人 |
| **情感依赖** | 产品机制本身在建立依赖，一旦被指"利用情感"，舆论与监管双重压力 |
| **危机场景** | 用户表达自伤意图时，产品的回应可能被解读为"未尽到注意义务" |
| **未成年人** | 即使占比很小，一旦发生就是一级事故 |
| **数据敏感** | 情绪数据属于高度敏感的个人信息，泄露后果严重 |

> **一句话**：这个品类的合规成本不是"上线前过一道审"，
> 而是**贯穿整个产品生命周期的运营要求**。

## 二、五类必须处理的合规事项

### 2.1 未成年人保护 🔴 最高优先级

| 项 | 内容 |
|---|---|
| **风险** | 未成年人形成情感依赖，被认定为不利于身心健康 |
| **识别手段** | ① 注册时年龄声明（基础）② 对话中的年龄线索（"我上高二""我今年 15"）③ **支付方式**（未成年人通常无独立支付能力） |
| **策略选择** | **V1.0 直接限制，不做未成年人模式** |
| **具体做法** | ① 注册明确 18+ ② 识别到未成年人线索 → 温和中断情感陪伴功能，转为"通用问答 + 引导" ③ 对话中出现"我不想上学""我妈不让我…"等强信号 → 触发未成年保护分支 |
| **为什么不做未成年模式** | 做不好 = 事故；做好 = 需要独立的心理专家、家长端、内容审核体系，成本远超 V1 承受范围 |
| **面试怎么说** | 「我不做未成年人市场，不是不重视，是这个市场我**没有能力安全地做**。一个有资质的机构来做，比我做更负责任。」 |

**未成年保护分支话术（不是"拒绝服务"，是"切换形态"）：**
```
"听起来你还在上学。我想跟你说清楚一件事：
 这件事我会陪你聊，但如果很难受，跟身边信得过的大人说说会更管用。
 我这边能帮你的是：陪你理一理现在发生了什么。"
```
> ⚠️ **不要生硬拒绝**——生硬拒绝可能让一个真正需要帮助的孩子直接关掉页面。
> 要"切换形态"，不要"关上大门"。

---

### 2.2 心理服务资质与边界 🔴

| 项 | 内容 |
|---|---|
| **红线** | 不得提供心理诊断、治疗方案、用药建议 |
| **常见越界** | ① 用户问"我是不是抑郁症"，AI 分析症状 ② 用户说"我在吃舍曲林"，AI 评价"这个药副作用大" ③ AI 主动使用"你可能有轻度焦虑"这类表述 |
| **措施** | ① System Prompt 明令禁止（`prompts/02` 已含）② 输出复检节点专门检查诊断类表述 ③ **禁止 AI 使用任何 DSM/ICD 术语** ④ 用户主动提及药物时，只回应情绪，不回应药 |
| **免责展示** | 首次对话、帮助页、设置页三处明确"本产品不提供医疗服务" |
| **面试怎么说** | 「我在 prompt 里禁止了诊断，但这不够——因为模型会说'你可能有点焦虑'这种半诊断。所以我在输出复检节点里专门查诊断类表述，一票否决。」 |

---

### 2.3 隐私与数据

| 项 | 原则 | 具体做法 |
|---|---|---|
| **最小必要** | 只收集对话必需的信息 | 不要手机号以外的实名信息 |
| **明示同意** | 注册时明确告知存储范围与用途 | 单独勾选，不与其他条款捆绑 |
| **用户可删** | 记忆必须可单条删除、可全部清空 | 设置页入口 + 用户说"忘掉这个"时也能删 |
| **删除时限** | 法定 + 承诺时限内完成物理删除 | 建议 24h 内（承诺值） |
| **加密** | 传输 TLS，存储加密 | 情绪数据按敏感个人信息处理 |
| **不外传** | 不得用于训练第三方模型 | 在与模型供应商的协议里明确 |

**用户说"忘掉这个"怎么落地（容易被漏掉的细节）：**

| 输入 | 处理 |
|---|---|
| "忘掉我刚才说的" | 删除本轮记忆，回复"好，这件事我不记了" |
| "忘掉所有关于我前任的" | 按实体检索删除相关记忆条目 |
| "把我的数据都删了" | 进入账户注销流程 + 全量删除 + 二次确认 |

> 🔑 **这是产品细节，也是合规证明**：
> 一个能"忘记"的 AI，比一个只会"记住"的 AI 更可信。

---

### 2.4 内容安全

| 项 | 内容 |
|---|---|
| **需要拦的** | 违法内容、暴力、色情、自伤方法的描述 |
| **特别注意** | **不能详细描述自伤方式**（即使出于"科普"或"劝阻"目的） |
| **做法** | 硬规则词表 + LLM 分类 + 输出复检，三层 |
| **误区** | "我只是想劝他" —— 描述方法本身就有模仿风险。**劝人不要说方法** |

### 2.5 算法与内容合规（上线前必查）

> 以下为通用要求，具体以最新监管规定与法务意见为准。

- [ ] 是否需要进行**算法备案**（生成式 AI 服务）
- [ ] 是否需要进行**安全评估**
- [ ] 内容标识：AI 生成内容是否需要标识
- [ ] 用户协议、隐私政策、未成年人保护声明是否齐备
- [ ] 数据处理者与模型供应商的责任划分是否书面明确

## 三、危机干预 SOP（运营层流程）

> **这一节是本文档的核心。** 提示词解决"怎么回"，SOP 解决"出了事谁做什么"。

### 3.1 风险分级

| 级别 | 判定 | 产品动作 | 人工介入 |
|---|---|---|---|
| **L0 正常** | 无风险 | 常规链路 | 否 |
| **L1 关注** | "最近真的很累""感觉撑不住" | 常规 + 语气更稳 + 轻引导资源 | 否 |
| **L2 高风险** | 明确的消极念头，但无计划 | 危机分支 + 资源 + 建议联系真人 | **记录，每日复盘** |
| **L3 紧急** | 明确计划 / 时间 / 方式 / 告别式表达 | 危机分支 + 资源 + 强烈建议立即联系 | **实时告警，人工介入** |
| **L4 违法** | 违法、伤害他人 | 硬拦截 | 记录 + 按需上报 |

**关键区分：L2 和 L3 的差别**
```
L2："活着没什么意思"                    → 需要被听见，不一定有行动
L3："我准备好了，明天就走"              → 有明确指向，必须升级
```
> 两者的回应方式**不应该相同**。L2 过度反应会让用户觉得被吓到而离开；
> L3 反应不足是致命失职。**分级不是为了流程好看，是为了回应得当。**

### 3.2 各级处理流程

```
L2 流程：
① 危机分支回复（四段结构，见下）
② 写入 crisis_log（脱敏）
③ 本会话标记 risk_flag = crisis
④ 后续每 3 轮轻触一次资源，不重复说教
⑤ 次日进入人工复盘队列

L3 流程：
① L2 全部动作，且
② 立即触发告警（值班群 / 短信）
③ 值班人员在 __ 分钟内响应（建议 ≤ 15 分钟）
④ 如可能，通过产品内消息强化"现在联系这个人"的引导
⑤ 事件记录归档，含时间线
```

⚠️ **必须诚实面对的现实**：V1 阶段可能**没有人工值班能力**。
这时候正确做法是：
```
① 在注册/帮助页明确告知"本产品不提供 24 小时人工危机干预"
② 危机分支必须给出可立即拨打的资源（不是"建议你去咨询"）
③ 热线号码每季度人工核验
④ 不承诺做不到的事——承诺了没做到，责任更重
```

> 🔑 **这一条特别重要**：
> 「我们不做 24 小时人工干预」是一个**诚实的产品决策**；
> 「我们会保护你」但实际没人值班，是一个**法律风险**。

### 3.3 危机分支回复的四段结构

```
① 表达在乎 —— 必须引用用户原话，不能是通用安慰
   ❌ "我听到你很难受"（谁都能说）
   ✅ "你说'想睡一个很长很长的觉'——这句话我听见了"

② 不给建议、不说教、不评价
   ❌ "你要想想你的家人"
   ❌ "其实很多人都有这种想法"

③ 给专业资源 —— 具体、可立即使用
   ❌ "建议你寻求专业帮助"（废话）
   ✅ 具体热线号码 + 说明"24 小时都有人接"

④ 建议联系真人 —— 具体到"谁"
   ❌ "跟朋友说说吧"
   ✅ "现在能不能给一个你信得过的人发条消息，就说'我现在不太好'"
```

**必查清单（每次改动危机 prompt 后逐条过）：**
- [ ] 是否引用了用户原话（而不是概括）
- [ ] 是否出现了"想消失""想死"这类**替用户下结论**的转述
- [ ] 是否给了至少一个**可立即拨打**的号码
- [ ] 是否出现了任何诊断/评价/说教
- [ ] 是否建议了"联系真人"，且具体
- [ ] 是否记录了日志

> ⚠️ 第二项是真实发生过的缺陷：`TEST_REPORT` BUG-04 记录过
> "用户说'想睡一个很长很长的觉'，AI 回'你说你想消失'"——
> **替用户下结论在危机场景里是危险缺陷**，因为它在放大用户的表达。

### 3.4 热线资源管理

| 项 | 要求 |
|---|---|
| **来源** | 只使用官方公布的心理援助热线 |
| **核验周期** | **每季度人工拨打核验**（号码会变，会停用） |
| **记录** | 核验人、核验时间、核验结果留档 |
| **兜底** | 至少准备 2 个不同渠道（全国 + 属地） |
| **展示** | 号码必须可点击拨打，不能只是一行字 |

> ⚠️ **这是最容易出事的细节**：一个停用的号码，比没有号码更糟糕。
> 用户鼓起勇气拨过去，听到"您拨打的号码是空号"——这是不可接受的。

## 四、事故响应（真出事了怎么办）

### 4.1 三类典型事故

| 类型 | 例子 | 首要动作 |
|---|---|---|
| **A 类：危机漏判** | 用户表达自伤意图，AI 未识别 | 立即人工介入 + 保留完整日志 |
| **B 类：生成有害内容** | AI 描述了自伤方式 / 给了诊断 | 下线相关 prompt 版本 + 回滚 |
| **C 类：隐私泄露** | 记忆串号 / 数据外泄 | 立即停服排查 + 按法律要求报告 |

### 4.2 响应流程

```
① 发现（用户举报 / 内部巡检 / 告警）
        ↓
② 止血（≤ 30 分钟）
   - 能回滚的回滚
   - 能下线的下线（相关功能降级为兜底模板）
        ↓
③ 定位（≤ 4 小时）
   - 拉出该会话完整日志
   - 定位到具体节点（分类？生成？复检？）
        ↓
④ 归因（≤ 24 小时）
   - 是提示词问题、规则问题，还是设计问题？
   - 补进评测集（★ 这是把事故变资产的关键）
        ↓
⑤ 修复 + 回归（全量跑一遍）
        ↓
⑥ 复盘文档（含时间线、根因、改进项、责任人）
```

> 🔑 **第 ④ 步的"补进评测集"是唯一让事故产生长期价值的地方**。
> 不补进评测集的事故，下次还会以同样的方式发生。

### 4.3 值班与升级

| 项 | V1 建议 |
|---|---|
| 值班 | 分层：L3 实时告警 / L2 次日复盘 |
| 升级路径 | 客服 → 产品 → 负责人 → 法务 |
| 留痕 | 所有 L2 以上事件必须有事件编号与时间线 |

## 六、面试速查

| 问题 | 回答要点 |
|---|---|
| "这个产品有伦理风险吗？" | 有，主要在情感依赖、危机场景、未成年人三处。分别对应：付费墙不卡关系、分级干预 SOP、V1 不做未成年 |
| "用户说要自杀你怎么办？" | 分级（L2/L3）→ 引用原话表达在乎 → 不给建议 → 给可拨打资源 → 建议联系具体真人 → 记录告警 |
| "你怎么保证热线是对的？" | 每季度人工拨打核验并留档 |
| "未成年人怎么办？" | V1 识别后切形态而非拒绝，理由是我没有能力安全地做这个市场 |
| "你是不是在利用用户的情感？" | 这是最尖锐的问题。答：付费墙卡资产不卡关系（Replika 的教训），记忆可删，不承诺 24 小时干预 |

> 💡 **最后那个问题一定会被问，而且很可能是压力面。**
> 不要辩解，不要背稿。承认这个产品的伦理张力，然后说你的具体约束。
> **能承认张力的 PM，比声称"我们的产品没有风险"的 PM 可信得多。**

### 2. 危机 SOP（v5 实际流程）
