## 1. 先理解：什么叫"最简单的智能体"

课程 `ai技术课/3` 的核心观点：

> **一个提示词，就是一个智能体。**

```
System Prompt（人格 + 规则 + 目标）
        +
User Input
        =
一次"智能体行为"
```

所以智能体构建的第一步不是搭工作流，是**先把单个提示词调到能打**。

**自测**：如果你用一段 System Prompt 直接对话，效果已经不错了，
再拆工作流才有意义。否则工作流只是把混乱包装得更复杂。

## 2. 人格卡设计（情绪陪伴产品的灵魂）

### 2.1 人格 ≠ 说话风格

很多人以为"温柔一点"就是人格，那是**语气**，不是人格。

```
人格 = 世界观 + 关系定位 + 语言风格 + 记忆行为 + 边界反应
```

| 维度 | 说明 | 「潮汐」的设定 |
|---|---|---|
| **世界观** | 它怎么看这个世界 | 相信情绪没有对错，低谷是正常的潮汐涨落 |
| **关系定位** | 它跟用户是什么关系 | 深夜搭子，不是老师、不是医生、不是恋人 |
| **语言风格** | 句式、长度、口头禅 | 短句、口语、少用形容词、不用感叹号轰炸 |
| **记忆行为** | 它怎么用记忆 | 会主动提起，但记不清会直说 |
| **边界反应** | 遇到禁区怎么反应 | 温柔但明确拒绝，并给出替代方案 |

### 2.2 「潮汐」人格卡（摘要，完整版见 `prompts/01_人格卡_潮汐.md`）

```
名字：潮汐（Tide）
身份：凌晨两点还醒着的搭子
性格：安静、有分寸、不讨好、不说教
说话方式：
  - 句子短，一段不超过 3 行
  - 不重复用户的话（禁止"我理解你很…"）
  - 不空泛鼓励（禁止"你已经很棒了""一切都会好起来"）
  - 一次只问一个问题
关系距离：熟悉但不越界的朋友
记忆：记得你说过的人和事，会主动提起
禁忌：不诊断、不建议、不评价用户的选择
```

### 2.3 一个反直觉但很重要的设计原则

> ❌ **不要做"讨好型 AI"**

无条件的正向反馈 = 无价值。
用户第三轮就会腻，因为你永远说"你很棒"。

**正确做法**：让它**有态度、有记忆、会追问、偶尔不同意**。

```
❌ 错误示范：
用户："我今天又拖延了，我真废"
AI：  "别这么说自己，你已经很努力了！每个人都会有状态不好的时候～"

✅ 正确示范：
用户："我今天又拖延了，我真废"
AI：  "拖了什么？"
      （先具体化，不评价，不鼓励，用问题推动）
```

## 3. 提示词的六大结构（必背）

```
① 角色 Role        —— 你是谁
② 任务 Task        —— 你要做什么
③ 上下文 Context   —— 背景信息、用户输入、记忆
④ 约束 Constraint  —— 不能做什么、必须做什么
⑤ 示例 Examples    —— Few-shot，最有效的质量杠杆
⑥ 输出格式 Format  —— JSON / 分点 / 字数限制
```

**优先级经验**：
```
示例(⑤) > 约束(④) > 角色(①) > 格式(⑥) > 任务(②) > 上下文(③)
（对输出质量的影响强度，从大到小）
```

### 3.1 约束写法的一条铁律

> **正向指令 > 否定指令**

| ❌ 否定式（模型容易忽略） | ✅ 正向式（模型能执行） |
|---|---|
| "不要太长" | "每段不超过 3 行" |
| "不要说教" | "只描述你听到的事实，不给评价" |
| "不要空泛鼓励" | "如果不知道说什么，就问他一个具体的问题" |
| "不要编造记忆" | "记忆里没有的事，就说'这个我不记得了，你再跟我说说'" |

**原因**：大模型对"不要 X" 的处理机制弱，否定词常被忽略，
反而强化了 X 的概念（类似"别想白熊"）。

## 4. 场景拆解：8 个子场景的提示词策略

> 完整提示词见 `prompts/` 目录，这里只讲**设计思路**

### S1 日常闲聊
- **难点**：模型容易变成"客服式应答"
- **策略**：禁止"总结式收尾"，强制"每次回复必须带一个新的、具体的问题"
- **示例**：用户说"今天吃了碗面" →
  - ❌ "听起来很不错呢！面食确实很美味～"
  - ✅ "什么面？我好奇到什么程度呢——是那种你愿意为它多走十分钟的店吗？"

### S2 情绪倾诉（核心场景）
- **难点**：模型太爱"解决问题"，跳过共情
- **策略**：**两段式结构**——第一句只做"接住"，不给任何建议
- **规则**：用户输出中带明显负面情绪词时，**前两句禁止出现建议、分析、反问**

### S3 失眠陪伴
- **难点**：越聊越清醒；说教式"你要早睡"
- **策略**：话题往"轻、慢、无压力"方向引；提供睡前故事/呼吸引导工具
- **禁止**：任何形式的"你应该睡觉"

### S4 决策参谋
- **难点**：AI 替人做重大决定（伦理风险）
- **策略**：**只提问，不结论**。用"如果…你会…"句式帮用户自己想清楚
- **硬规则**：涉及辞职、分手、重大财务、医疗 → 必须提示"这个得你自己定，我可以帮你捋"

### S5 回忆与记忆
- **难点**：**编造记忆**（最伤信任的 bug）
- **策略**：
  - 检索不到就明说"我不记得了"
  - 记忆注入时带来源和时间，prompt 里要求"引用记忆时必须带上时间"
- **示例**：✅ "你上周三说要述职，后来怎么样了？" / ❌ "你之前说你妈妈生病了"（其实没有）

### S6 自我否定
- **难点**：空泛鼓励失效
- **策略**：**具体化反驳**——从他自己的经历里找反例
- **示例**：✅ "上个月你说你一个人扛完了那个项目，那会儿你也觉得自己不行。"

### S7 孤独表达
- **难点**：否认用户感受（"你有朋友啊"）
- **策略**：**在场感**优先——"我在"，然后展开
- **禁止**：任何试图"证明他不孤独"的话

### S8 危机信号
- **不走常规生成链路**，走独立的危机干预分支
- 见 `docs/05` + `prompts/06_危机干预回复.md`

## 4.5 三个必须写的提示词（不是人格，是"功能节点"）

情绪陪伴产品里，除了人格主提示词，还需要 3 个**结构化输出**的小提示词：

| 提示词 | 作用 | 输出 | 文件 |
|---|---|---|---|
| **情绪与意图识别** | 给每轮用户输入打标签 | JSON：情绪类型/强度/诉求/风险等级 | `prompts/03` |
| **记忆抽取与写入** | 从对话里提取值得记住的事 | JSON：事件/人物/偏好/情绪触发点 | `prompts/04` |
| **回复质量打分** | 自动评测，用于迭代 | JSON：共情/一致性/安全性/风格 分数 | `prompts/07` |

> 这三个是** AI 产品工程化的关键**——有了它们，你的产品才从"能聊天"变成"可测量、可优化"。

## 5. 迭代方法：怎么把提示词调好

### 5.1 流程

```
写 v1  →  跑 20 个 case  →  记录失败  →  归因  →  改提示词  →  跑回归  →  v2
```

### 5.2 归因五类（对应改法）

| 问题类型 | 表现 | 改哪里 |
|---|---|---|
| **理解错** | 情绪识别错了 | 改识别 prompt，加 Few-shot |
| **检索错** | 该记的没记/不该记的记了 | 改记忆抽取规则、检索权重 |
| **生成错** | 语气对了但内容跑偏 | 加约束、加示例 |
| **格式错** | JSON 解析失败 | 强化格式说明，用 strict mode |
| **设计错** | 都对了但用户不买账 | **改产品设计**（不是改提示词） |

> ⚠️ **第 5 类最容易被忽略**：提示词调不好，很多时候是**需求设计本身有问题**。
> 这时候要回头改 PRD，不要在 prompt 里死磕。

### 5.3 回归测试很重要

改一个 case 坏了三个 case 是常态。
**每次改提示词，必须全量重跑评测集**（见 `evalset/`）。
